## E-01 ナビゲーション・PWA・共有

| 機能名 | 要件・動作仕様 |
| :--- | :--- |
| **E-01-01 URLパラメータによるモード直接起動** | ・URLクエリパラメータ `mode`（例: `?mode=district`, `?mode=rep`, `?mode=neighbor`, `?mode=transfer`、および数値エイリアス `?mode=1`, `2`, `3`, `4`）を最優先で解釈して起動。<br/>・外部共有リンク（学校からの案内メール、LINE連絡等）を踏んだ際、役員や転入家庭がモード選択で迷うことなく、目的の画面を直接開くことが可能。<br/>・URLパラメータが指定されていない場合は、従来通り前回選択モード（`kogai_active_mode`）を復元。 |
| **E-01-02 モード指定URL共有機能** | ・ヘッダー右側の「🔗 アプリを共有」ボタンおよび各画面内の共有UIにおいて、特定モードを指定したURL（例: `https://.../?mode=transfer`）の生成・共有に対応。<br/>・Web Share API（`navigator.share`）、クリップボードコピー、コピー非対応時のプロンプト案内に対応。LINE・メール等のアプリ選択はOS共有先に依存する。 |
| **E-01-03 モード選択肢の動的折りたたみUX** | ・初期画面およびモード選択時、ヘッダー直下の4モード選択ボタンが自動的にコンパクトな「アクティブモード表示バッジ（例：`① 各地区役員モード ▼ [モード切替]`）」へと折りたたまれる。<br/>・スマートフォン等の狭小画面において、作業領域（名簿テーブルや入力フォーム）の視認性を劇的に向上。<br/>・バッジをクリックすると即座に4つのモード選択ボタンが展開され、いつでも自由に他モードへ移動可能。 |
| **E-01-04 前回選択モードの永続化と自動復元** | ・`switchTab(mode)` 実行時に選択されたモード（`district`, `rep`, `neighbor`, `transfer`）を `localStorage.setItem('kogai_active_mode', mode)` として永続化。<br/>・次回アクセス時やページ再読み込み時（`DOMContentLoaded`）、直前に開いていたモードを自動復元し、同一画面から作業をシームレスに再開可能（URLパラメータ指定時はURLパラメータが最優先）。 |
| **E-01-05 アプリ共有機能（PWA対応）** | ・PWAインストール後（スタンドアロン起動時）にブラウザのアドレスバーが消滅し、他の役員へURLを伝えられなくなる問題を解消。<br/>・ヘッダー右側に「🔗 アプリを共有」ボタンを常設。<br/>・Web Share API（`navigator.share`）により、LINE、メール、AirDrop等へワンタップでアプリURLおよび紹介文を送信可能。<br/>・Web Share API非対応ブラウザではクリップボード自動コピーおよびプロンプトフォールバック。 |
| **E-01-06 PWAバージョンチェック＆強制・手動アップデート機構** | ・**課題の根本解決**: PWAインストール（スタンドアロン起動）環境下において、Service WorkerやブラウザのHTTPキャッシュにより新版が反映されない問題を解消。<br/>・**`version.json` による静的バージョン公開**: サーバー直下に `version.json`（`version`, `updatedAt`, `description`）を配備。Service Workerキャッシュから除外し、常に最新の公開バージョンを取得。<br/>・**起動時自動チェック（オンライン時）**: アプリ起動時（DOMContentLoaded後1秒遅延）、`navigator.onLine` が有効であればキャッシュ無効化クエリ（`version.json?_t=${Date.now()}`）で自動取得。現在のバージョン（`CURRENT_APP_VERSION`）と比較し、最新版があれば確認ダイアログを表示し、OK選択時に強制アップデート。<br/>・**設定欄最下部の手動確認＆更新UI**: セキュリティ設定モーダル最下部に「📱 アプリバージョン情報」セクションを常設。現在のバージョン表示と「🔄 最新バージョンを確認・更新」ボタンを配備。手動クリック時に即時チェックし、最新版更新または最新状態フィードバックを提供（オフライン時はエラー通知）。<br/>・**保存完了後のアップデート (`performAppUpdate`)**: 更新実行前に必ず `saveDistrictLocal()`, `saveRepLocal()`, `saveNeighborLocal()`, `saveTransferLocal()` の完了を待つ。保存失敗を通知して更新を中止する。当該アプリscopeのキャッシュ削除および当該SW登録の解除を行い、キャッシュバスティングパラメータ付きURLで最新版を再取得。<br/>・**無限更新ループ防止セーフティガード（フェイルセーフ仕様）**: `performAppUpdate` 実行時に `sessionStorage` へ更新試行対象バージョン（`kogai_update_attempted_version`）および試行時刻（`kogai_update_attempted_time`）を記録。リロード後の自動チェック（`checkAppVersion(false)`）時に、直前の更新試行記録が存在しかつ現在の `CURRENT_APP_VERSION` が依然として `remoteVersion` 未満である場合、キャッシュ未反映やデプロイ遅延等と判断して**自動更新ダイアログの表示をスキップ（抑制）**。手動更新チェック（`checkAppVersion(true)`）ではスキップせず常に再試行可能。最新バージョンへの更新成功時には試行記録を自動消去。<br/>・**HTTPキャッシュ制御**: `navigator.serviceWorker.register('./sw.js', { updateViaCache: 'none' })` により、ブラウザのHTTPキャッシュをバイパスして `sw.js` の変更を確実に検知。 |
| **E-01-07 全削除操作における安全確認セーフティガード** | ・システム内の全削除ボタン（集約地区削除、スクゾ関係者削除、自治会役員削除、児童名簿削除、転入児童削除）において、誤タップ・誤クリックによる即時消失を完全に防止するため、確認ダイアログ（`confirm`）を表示する。ただし未入力の転入下書き行は確認なしで削除できる。<br/>・キャンセル時は配列操作を行わず安全に中断。対象の名前等をダイアログ内に明示して誤削除を防止。 |

## E-02 各地区役員モード

| 機能名 | 要件・動作仕様 |
| :--- | :--- |
| **E-02-01 地区名・班名リスト管理** | ・地区名（例：1丁目、緑ヶ丘）を入力。<br/>・地区名直下にカンマ区切りの班名リスト（例：`A班, B班, C班`）を登録。<br/>・班名リストから児童名簿および校外役員の「担当班」プルダウンが自動生成される。 |
| **E-02-02 校外役員管理（複数人対応）** | ・1地区あたり2人以上の役員（各班担当等）を登録可能。<br/>・氏名・ふりがなを「姓 / 名」別に入力。<br/>・役職、担当班、電話番号、メールアドレス、住所、封筒受取用児童情報（学年・組・氏名）を完備。<br/>・入力と連動してカードヘッダーがリアルタイム反映。役員削除時は確認ダイアログを表示。 |
| **E-02-03 自治会役員統合取込UI（トグル開閉UX）** | ・**トグル展開UX**: カード2ヘッダーの「📥 自治会データを統合」をクリックすると、カード本体を展開しつつ、自治会統合パネル（`#d-neighbor-import-panel`、初期 `display: none`）の表示/非表示をトグル開閉。<br/>・**名簿直結の「＋ 行を追加」ボタン配置**: 統合パネルの初期非表示化に伴い、自治会役員名簿テーブルの直前（上部ツールバー）および直下（テーブルフッター）の双方に「＋ 行を追加」ボタンを配置し、スクロール負担なく行追加が可能。<br/>・**役員行削除確認ダイアログ**: 自治会役員行の「×」削除ボタン押下時、役員名を表示して確認ダイアログ（`confirm('自治会役員「' + name + '」を削除しますか？')`）を表示。キャンセル時は削除を中断。<br/>・**スマートフォン最適化**: 横幅狭小画面でもボタンやテキストが途切れないレスポンシブな縦並びレイアウト。ファイル読込ボタン（`📁 ファイルから統合`）とクリップボード貼付入力欄（`#d-neighbor-paste-box`、`📥 貼付テキストから統合`）を明瞭に分離配置。<br/>・**地区名不一致時の保護**: 自治会データ内の地区名と自地区名が異なる場合、警告・確認ダイアログを表示し、キャンセル時は安全に中断。<br/>・現在の児童名簿や校外役員データを一切破壊せず、自治会役員テーブルのみを最新情報に更新。 |
| **E-02-04 転入児童データ統合取込（トグル開閉UX）** | ・カード3「児童名簿」ヘッダーまたはツールバーに「📥 転入児童データを統合」トグルボタンを配置。<br/>・取り込みパネル（`#d-transfer-import-panel`）を初期非表示（`display: none`）とし、トグル開閉により名簿一覧の邪魔にならない設計。<br/>・転入家庭から受け取った暗号化ファイル（`.txt`）または暗号化テキストを復号読込。<br/>・**班割り当て選択**: 既存班を初期値とする入力ダイアログで割り当てる班を入力する。<br/>・転入家庭の児童（1名または複数名兄弟姉妹）を自地区の児童名簿へ安全に追記・ソート・自動保存。 |
| **E-02-05 児童名簿管理（名簿直結ボタン配置・削除確認）** | ・学年（1〜6年）、クラス、班、氏名（姓/名）、ふりがな（せい/めい）、住所、電話番号、役職（班長/副班長/一般）、学区外フラグを入力。<br/>・**名簿直結ツールバー＆フッター**: 児童名簿テーブルの直前上部に「🔽 並び替え」「＋ 児童を追加」ボタンを、テーブル直下フッターに「＋ 児童を追加」ボタンを配置し、名簿行とボタンが離れすぎない最適な視認性・操作性を実現。<br/>・**児童削除確認ダイアログ**: 児童行の「×」削除ボタン押下時、児童名を表示して確認ダイアログ（`confirm('児童「' + name + '」を名簿から削除しますか？')`）を表示。キャンセル時は削除を中断。<br/>・新規追加時は直前児童の班名を自動継承。<br/>・ソート優先順位: **① 班（自然順）**、**② 班長 → 副班長 → その他**、**③ 学年（6年→1年降順）**、**④ 住所（自然数値順）**、**⑤ クラス（自然数値順）**、**⑥ ふりがな（氏名を代替）**。<br/>・名簿最下部に「班の児童数」と「地区全体の児童数」および学区外児童数を自動併記。 |
| **E-02-06 自地区帳票の選択印刷＆個別PDF保存パイプライン** | ・**一括印刷**: 「🖨️ チェックした自地区帳票を印刷 / PDF保存」により、選択した帳票を連続改ページでまとめて印刷。<br/>・**個別PDF保存（`printSingleDistrictSeparately`）**: 「📄 選択した帳票を個別にPDF保存」ボタンを新設。チェックした各帳票（児童名簿、自治会役員名簿、校外役員学校用、校外役員PTA用）ごとに順次印刷プレビューを呼び出し、帳票ごとの単一PDFファイルとして分割保存可能。<br/>・**動的タイトル連動**: 各帳票の印刷実行直前に `document.title` を「`[帳票名]_[地区名]`」に一時変更し、PDF保存時のデフォルトファイル名が帳票名に自動連動。印刷後に自動復元。 |
| **E-02-07 旗振り当番シフト表（ハタフロットネイティブ統合・永続化・レスポンシブ）** | ・**データと設定の完全永続化**: `saveDistrictLocal()` 実行時に、画面上の入力値（タイトル、場所、時間、期間、向き、段数、ヘッダー、フッター、連絡先、祝日、特別枠）を確実に収集して `currentDistrict.hata` に同期し、LocalStorage（`kogai_district_v2`）および暗号化ファイルへ完全永続化。次回起動時・ファイル読込時にも確実に画面復元。<br/>・**デフォルト設定の最適化**: 印刷向きのデフォルトを「縦向き（`portrait`）」、段数のデフォルトを「2段（`layoutColumns: 2`）」に設定。<br/>・**レスポンシブUI改善**: スマホ画面での「テキスト形式（旧連携機能）」のテキストコピー行を縦並び（`flex-direction: column`）にしテキストボックスの狭小化を解消。操作ツールバー（シフト生成、印刷、JSON読込ボタン）をスマホ画面で整然とした均等グリッド/縦並びブロックに再編。<br/>・**PC表示時の2段グリッド化**: 除外祝日・行事日、特別追加枠、ヘッダー連絡事項、フッター連絡事項＆連絡先を、PC表示時に2カラム×2段グリッドレイアウト（上段: 祝日＋特別枠、下段: ヘッダー＋フッター）に分割し、大画面での視認性・入力性を大幅向上。<br/>・**PDF保存時の動的タイトル連動**: `printHataSchedule()` 実行直前に、`document.title` をシフト表タイトル（`hata.title`、例: `登校見守り活動シフト表`）に動的変更し、PDF保存時のデフォルトファイル名がアプリタイトルではなくシフト表タイトルになるよう改善。印刷後に自動復元。<br/>・**A4組版仕様**: 作成日、2行メタ情報テーブル、ヘッダー連絡事項、多段組（1〜6段、空行パディング整列）、状態別行（祝日グレー、特別枠オレンジ・★）、フッター連絡事項、破線枠校外委員連絡先、当番回数集計アコーディオン、公式JSONの読込。 |
| **E-02-08 地区データ保存・読み込み・年度更新（ジャンル別4大セクション整理）** | ・カード6の内部を機能ジャンルごとに明瞭に区切られた4大セクションとして整理・レイアウト：<br/>　**① パスワード設定・端末記憶**: ファイル保護用パスワード（12文字以上、可視化トグル、全角サニタイズ）、確認入力、端末暗号化ストレージ連動記憶チェックボックス。<br/>　**② 地区データの保存・出力・外部共有**: 「💾 ファイルを保存（.txt）」、「📱 LINEで共有」、「✉️ メールで送信」、「🔗 共有（Web Share）」、「📋 暗号化テキストをコピー」。暗号文が2,000文字を超える場合は自動でクリップボード退避＋定型文起動。<br/>　**③ 地区データの読み込み・復元**: 「📂 ファイルから読み込み」、「📥 貼付テキストから読み込み」。**既存hata保護マージ**: 読み込んだデータに `hata` がなく、ローカルに既存 `hata` がある場合は上書き消去せず保護・維持。<br/>　**④ 年度更新（新年度化）**: 「🌸 新年度へ更新（進級・卒業・役員初期化）」。6年生自動削除、1〜5年生進級、旧役員欄・記憶パスワードの安全クリア。**hata年度更新**: 活動場所・時間・曜日・連絡事項等の基本設定は維持し、期間・スケジュール・個別調整・特別枠を新年度用に安全初期化。 |

## E-03 校外代表モード

| 機能名 | 要件・動作仕様 |
| :--- | :--- |

## E-06 データ統合・情報共有の境界

- **E-06-01**: 地区→代表は旗振り設定（hata/hatafurotto）と記憶パスワードを除外する。代表→地区は対象地区だけを出力し、他地区・外部関係者・座席設定を含めない。地区読込データに旗振り設定がない場合は既存設定を維持する。
- **E-06-02**: 自治会は地区名不一致を確認してから置換する。転入児童は地区・班を割り当て、重複時に確認する。取消は旧状態を維持し、成功件数へ含めない。
- **E-06-03**: ファイルと貼付は同じ種別振分・復号・確認を通す。代表マスターは全体復元、地区は集約、転入は割当、自治会は自治会名簿の統合とする。
- **E-06-04**: 自治会年度更新は役職、代表年度更新は外部関係者の区分・所属・役職だけを保持し、正式個人項目を空にする。旧形式name/kanaと余剰連絡先・任意項目も引き継がない。取消時はすべて保持する。更新後の画面・保存・再読込・印刷・再暗号化出力で旧個人項目が復活しない。

### 6.3 PDF保存時の動的タイトル連動仕様 (Dynamic PDF Document Title)
1. **課題意識**:
	- ブラウザ標準の「PDFとして保存（Print to PDF）」機能では、出力されるPDFファイルのデフォルトファイル名として、ブラウザタブの `<title>` タグ（`document.title`）の値（例: `小ptidocs` や `kogaidocs`）が自動採用される。
	- これにより、役員が各種帳票や旗振りシフト表をPDF保存した際、ファイル名がすべて同一のアプリ名称となり、どのファイルがどの帳票であるかをファイルマネージャー上で手動リネームしなければならない運用負荷が発生していた。
2. **動的タイトル一時置換パイプライン**:
	- 各種印刷関数（`printHataSchedule()`, `printSingleDistrictSelected()`, `executeRepSelectedPrint()`, `printNeighborRoster()`, `printNeighborTentCards()` 等）の実行直前に、現在の `document.title` を退避した上で、出力帳票名および地区名を含む適切なファイル名用タイトルへ動的に一時置換する。
	- **命名パターン**:
		- 旗振りシフト表: `${hata.title || '旗振り当番シフト表'}_${districtName}`
		- 児童名簿: `児童名簿_${districtName}`
		- 自治会役員名簿: `自治会役員名簿_${districtName}`
		- 校外役員名簿（学校用）: `校外役員名簿_学校提出用_${districtName}`
		- 校外役員名簿（PTA用）: `校外役員名簿_PTA提出用_${districtName}`
		- 定例会名札: `四つ折り名札_${districtName}`
		- 代表モード一括: `校外代表帳票_${selectedSummary}_${dateStr}`
	- `window.print()` 呼出完了後、同期的に（および `onafterprint` またはタイマーによるフォールバック保護付きで）元の `document.title` へ確実に復元する。

### 6.4 複数帳票の個別PDF保存パイプライン (Granular Separate PDF Export)
1. **課題意識**:
	- 地区役員モード等において複数の帳票（児童名簿、自治会役員名簿、校外役員学校用、校外役員PTA用）にチェックを入れて印刷を実行すると、紙の印刷時には一括出力が便利である一方、PDF保存の際にはすべてが1つの巨大なPDFファイルに結合されてしまう。
	- 学校へ提出するファイル、PTAへ提出するファイル、自治会へ共有するファイルは配布先が異なるため、帳票ごとに分割された単一PDFとして保存できる仕組みが強く求められていた。
2. **個別PDF保存パイプライン（`printSingleDistrictSeparately`）**:
	- 「🖨️ チェックした自地区帳票を印刷 / PDF保存」（一括出力）ボタンの隣に、「📄 選択した帳票を個別にPDF保存」ボタンを新設。
	- チェックされた各帳票を配列化し、1帳票ずつ `#print-area` にレンダリングし、対応する動的タイトルを設定して順次 `window.print()` を起動。
	- ユーザーがブラウザの印刷/保存ダイアログで保存を完了するごとに、次の帳票の保存ダイアログが立ち上がり、チェックを入れた全帳票を個別のPDFファイルとしてスムーズに保存可能とする。

## E-08 パスワード・暗号化提出・端末保存・ロック

- **E-08-01**: パスワードは最低12文字、ASCII U+0021〜U+007Eである。大文字・小文字・数字・記号の混在そのものは必須としない。空白・日本語を許可しない。確認不一致は出力しない。可視化、全角ASCIIの半角化、非ASCIIの除去とカーソル位置保持を行う。
- **E-08-02**: 提出本文は `BEGIN_DATA:` と `:END_DATA` の間に暗号文を置く。誤鍵・短すぎる暗号文・未知形式・改竄は失敗とし、平文へ切り替えない。地区等の提出ファイル名と平文ヘッダーには地区・班・出力日が含まれ得る。本文の暗号化はこれらを秘匿しない。家庭情報ファイル名は個人名を含まない固定名である。
- **E-08-03**: 地区・代表モードでは端末データベースの暗号化設定を必須とする。設定・解除前は役員フォームを非表示かつ操作不能とし、モード選択は利用可能である。初回設定では端末上のデータベース用であり、出力・提出用ではないと説明する。全4モードを保護し、旧平文データを暗号化へ移行する。途中失敗は旧値を保持し、暗号化済み表示にしない。全消去後に待機中の旧自動保存でデータを復活させない。
- **E-08-04**: 暗号化解除はパスワードまたは対応環境のWebAuthn PRFで行う。誤認証、保存改竄、いずれかのモードの不正構造は部分表示せず失敗する。Web Locks非対応環境では暗号化の設定・解除・保存等を拒否して対応ブラウザを要求する。
- **E-08-05**: 記憶パスワードは暗号化解除中に明示同意した場合だけ保持する。未暗号化保存・代表集約へ渡さず、地区年度更新では保存対象から除外し、ロックではメモリと入力欄から消去する。暗号化保存済みの値は正しい解除後に復元できる。登録済みストレージの認証を共用し、パスワード記憶のための別WebAuthn登録は行わない。
- **E-08-06**: ロックは鍵、4モードの個人情報、旗振り表、座席・外部関係者、編集下書き、印刷領域、全パスワードと貼付を消去する。再起動・手動・15分非操作後の最初の操作でも強制し、期限切れ後の操作で延長しない。他タブの保護変更・全消去を検知したタブも破棄する。

## E-09 不信入力と失敗時の保全

- **E-09-01**: 認証済み暗号文の中身も不信入力である。ファイル/貼付、公式JSON、平文/暗号化保存値を同じ制約で検証する。型不一致、予約キー、容量・深さ・件数超過、不正な座席寸法を拒否する。上限値は内部仕様I-03で定める。
- **E-09-02**: 旗振り開始日・終了日は、片側だけの入力でも空でなければ実在する `YYYY-MM-DD` を要求する。両側指定時は開始日以下でない終了日、3,660日以内とする。休日省略時の自動補完は開始年2000〜2099だけで実行し、翌年補完も2099までとする。範囲外の有効な日付は受け入れ、休日は空へ補完する。明示した休日と空文字は維持する。対象年の制限は技術上の実行範囲であり、法改正・特例を含む暦の正確性保証ではない。
- **E-09-03**: 取込失敗時は旧4モード・DOM・保存原本を維持し、エラーを通知する。ロック・全消去をまたぐ非同期結果は反映しない。公式JSONの成功・失敗ともファイル選択をクリアして再選択を許す。地区貼付欄は成功時だけ消去する。
- **E-09-04**: 氏名・住所・メモ等のタグ、引用符、イベント風文字列は通常文字列として表示・印刷・保存する。攻撃DOM・コード・暗黙の送信先にしない。アプリURL共有には名簿、パスワード、暗号化本文を混入させない。

仕様と実行結果は[トレーサビリティ](specification_traceability.md)で区別する。OS印刷・共有先・実認証器とHTTP配信での挙動はローカルUI試験だけで保証しない。

## E-02-10 旗振り設定の完全統合（R-08）

- 基本設定に作成日、シフト表の地区名、複数行の時間、月〜日の曜日選択、1〜6段の列数を設ける。曜日全解除は特別枠だけを生成する。
- 当番名簿を詳細設定の外に表示し、1行1担当者として編集する。重複氏名をテキスト警告する。児童名簿の世帯一覧反映は明示ボタンで行い、既存の非空名簿を置換する際は確認する。
- シフト再生成・再描画・印刷で編集名簿を上書きしない。印刷とLINEコピーは最新の設定から生成する。PDFファイル名はタイトル・印刷地区名・作成日を含み、ファイル名に使用できない記号を置換する。コピー失敗時は本文を選択できる欄を表示する。
- 上流JSONの `title/createdDate/district/location/time/orientation/layoutColumns/headerMsg/footerMsg/contactMsg/members/holidays/specials/startDate/endDate/weekdays` と旧aliasを読み込む。ハタフロットJSONの保存ボタンと出力APIは提供しない。免除・手動調整・コピー形式・世帯集約設定も保存する。空文字と空配列も設定として保持する。
- 地区の暗号化エクスポートは全旗振り設定を保存する。代表集約からの除外はE-06-01に従う。ファイル未保存の変更を表示し、離脱時にブラウザの確認を要求する。端末自動保存とファイル保存を区別する。

## E-01-08 iPhone/iPadのホーム画面追加（R-16）

安全な配信環境のiPhone/iPadでは「ホーム画面に追加」ボタンでSafariの共有メニューによる追加手順を開く。案内は閉じるボタンまたはEscapeで閉じられる。standalone起動ではボタンを隠す。対応ブラウザでは従来のインストールプロンプトを利用する。file起動ではボタンを表示しない。Apple向けアプリ名・standalone指定・アイコンをHTML headに含める。HTTP応答ヘッダーを必須とするものではない。

## E-01-09 LINE内ブラウザ警告と途中入力の移動（R-17）

- UAの `Line/<version>` を検知した場合に警告を表示する。警告とヘッダーから暗号化引き継ぎdialogを開ける。代表の未確定名簿編集画面と地区追加画面にも引き継ぎボタンを置く。
- 暗号化データを作成し、ファイル保存またはコピー後に通常ブラウザを開く。移動用URLは同一アプリとモード、`openExternalBrowser=1` のみを含む。LINEのメニューから開く代替手順も案内する。自動移動・復元は主張しない。
- 移動先でファイルまたは貼付とパスワードから復元する。誤鍵・不正型・取消・保存失敗では旧モデル・DOM・保存値を維持する。正しいデータも既存4モードの置換確認を要求する。
- 地区・全旗振り設定・代表・自治会・未完了転入者、代表名簿の未確定編集と貼付欄・地区追加名の下書きを引き継ぐ。未完了の転入者には提出時の必須項目検査を適用しない。パスワード・端末暗号化設定・未読込ファイルは再入力する。
- dialogを閉じる・Escape・ロックでパスワードと生成結果を消去し、古い非同期処理の再表示を拒否する。引き継ぎ元は保存・コピー完了後もデータを自動消去しない。

## E-02-11 当番名簿と未完成入力

当番名簿の直上に書式指定と同一世帯まとめを配置し、児童名簿の反映ボタンでのみ適用する。既存名簿の置換は確認する。別の名簿プレビュー・テキストコピー・旧連携見出しを表示しない。シフトのプレビューは保持する。日付・休日・特別枠の入力が未完成、不正、逆順または展開上限超過の場合は入力を下書きとして残し、欄外へ修正案内を表示する。修正完了時に有効設定へ反映する。未完成のまま自動生成・LINEコピー・印刷を押した場合は修正を案内し、古い設定による出力を行わない。

免除候補は実際の当番名簿にある担当者を一意に列挙する。独自書式・手入力した担当者も対象である。児童名簿を編集しても、明示反映するまで当番名簿・免除候補を置き換えない。

## E-02-12 旗振りの入力・展開上限

当番名簿は10000担当者以下、担当者・書式・休日/特別枠の各行は4096文字以下とする。名簿本文・書式反映の結果はUTF-8で1MiB以下とする。最長の担当者と注記を全日付へ配置する保守的な見積もり、および実シフトの反復表示値も1MiB以下とする。上限超過の取込は確定前に拒否する。編集中の名簿・書式は下書きで保持し、修正前に生成・出力を実行しない。

保存ファイルの取込と自治会・転入統合は、検証済み候補の保存完了を待ってから本状態と画面へ反映する。失敗した場合は元のモデル・画面・保存原本を保ち、保存失敗を通知して再試行を可能とする。

班・氏名・住所等の短文は4096文字以下とする。班選択肢の行数との積は4MiB、全候補参加者の座席数との積は16MiBの保守的な見積もりで制限する。名簿・日付指定の改行分割は空行も含め10000行以下とする。

## E-10 アクセス保護とモバイル操作

- **E-10-01**: 設定・解除画面の「閉じてモードを選ぶ」、自治会・家庭情報入力への移動ボタンを常時利用可能とする。閉じても地区・代表フォームは開放されない。未解除で自治会・家庭情報入力へ移動した場合は空のフォームと「入力はこの画面限りであり、再読込で消える」旨を表示する。保存済み暗号文を変更しない。
- **E-10-02**: 初回暗号化の短い・不一致パスワード、暗号化・保存失敗はフォームを開放しない。既存の保存値は保持する。解除失敗も同様である。パスワード欄は閉じる・モード変更・成功時に消去する。
- **E-10-03**: 当番回数は展開時に高さを画面へ収め、縦スクロールで全員を確認できる。長い氏名は折返す。開閉を繰り返しても集計値を変更しない。
- **E-10-04**: バージョン確認は初期化から独立して実行し、取得・本文読込とも合計5秒で打切る。自動確認の失敗では操作を遮断しない。手動確認は失敗を表示して再試行可能とする。
- **E-10-05**: フォーム以外をuser-select:noneとし、通常の選択・コピー・切取を抑止する。input/textareaでは通常操作を維持する。スクリーンショットとコピーの失効保証はできない旨を設定画面へ表示する。期限付きクリップボード消去は、他のコピーの破壊やブラウザ停止時の不履行を避けるため実装しない。
- **E-10-06（SEC-25）**: 未暗号化端末の家庭情報入力・自治会モードからはブラウザ引き継ぎ作成およびアプリ更新を実行可能とし、出力に地区・代表データや役員下書きを含めない。未暗号化先ブラウザへの引き継ぎ復元は、家庭情報入力・自治会データのみの場合に限り役員平文キーへ書込まず許可し、地区・代表データを含む場合は暗号化設定を要求して拒否する。
- **E-10-07（SEC-26）**: ロック中のワンクリック暗号化適用はロック解除モーダルを開き、既に解除済み時・新規設定時の双方で自治会・代表からの呼び出しにより地区側記憶パスワード等を汚染しない。暗号化設定・生体認証登録中にモーダルを閉じたりロックされた場合は完了時の鍵有効化・設定書込み・再表示を行わない。
- **E-10-08（SEC-27）**: ロック中へ移行した場合は、遅延完了した暗号化コピー・LINEコピーの通知・代替選択表示、読込失敗後の復号パスワード再入力プロンプトや再描画、役員印刷（地区・代表・旗振り）および複数帳票個別PDF出力の後続印刷を抑止し、`#print-area` を消去する（自治会印刷（自治会役員名簿・名札印刷）はE-10-01に従い維持）。代表切り出し出力で `#rep-pass` を参照する場合は `#rep-pass-confirm` との確認パスワード不一致を検証し、2,000文字超のLINE/メール共有時はクリップボードへ退避する。
- **E-10-09（SEC-28）**: ロック、年度更新、家庭情報リセットおよび引き継ぎ復元時には、可視化されていたパスワード欄を `type="password"` と `👁️` 表示へ戻し、判定メッセージ、LINE用テキスト欄、印刷領域（`#print-area`）を完全に消去する。
- **E-10-10（SEC-29）**: 旗振りのメタ・書式文字列項目（複数行入力を含む `strings` 群のうち `specials` を除く全項目）・免除・手動調整・座席設定文字列・転入メモの文字長を4,096文字以下で検証し、`specials`・文字列形式 `holidays`・`members` の行リストは `validateHataTextBudget`（1行4,096文字・最大10,000行・1MiB以下）で検証する。対応する単一行入力欄へ `maxlength="4096"` を設ける。代表詳細モーダル保存時は全代表データスキーマ検証を通過しない限り本状態へ確定しない。暗号化中のストレージ欠損・他タブによる個別キー削除・不正バージョン形式・別オリジンまたは別スコープ送信元のSWメッセージを拒否する。


## E-11 長文復旧・共有失敗・次年度名簿作成（R-21・R-22）

- 旗振りのタイトル・作成日・地区・場所・時間・ヘッダー・フッター・連絡先の入力上限は4096文字である。プログラム入力等で上限を超えても全文を下書きとして保存し、有効設定と分離する。旧保存値の同項目の長文も全文を下書きへ移し、解除時に各名簿を復元できる。下書き修正までは状態案内を表示し、旗振り印刷・LINE出力を止める。修正後に有効設定へ戻す。
- 地区切り出しの2000文字超のLINE・メール共有は、コピーが拒否された場合またはAPI不在の場合、外部アプリを起動せず失敗を通知する。利用者は再試行または既存のファイル保存を選択できる。ロック後は通知も出さない。
- 地区カード3に「児童名簿を追加」のファイル入力を設ける。通常読込で次年度役員ファイルを開いた後、同アプリの地区形式 `.txt` から児童だけを追記する。取込時に進級・卒業生削除は行わず、学年・組・班・班長・学区外情報を維持する。役員、自治会、地区・班設定、旗振り、保存パスワードは変更しない。
- 取込元と現在の地区名が異なる場合は確認文に明示する。追加件数と既存児童を保持する旨を確認して一括追加する。既存児童と同姓同名・同学年の行がある場合は重複の可能性も明示する。自動的な統合・削除は行わない。
- 児童0件、代表・家庭情報・自治会ファイル、型や容量上限の違反は拒否する。確認取消・誤パスワード・保存失敗・ロックの場合は全既存モデルと保存値を維持し、ファイル欄を空に戻して再選択可能とする。

## E-12 保存値の復元可能性・取込値の信頼範囲（R-23）

- **E-12-01 構造操作の事前検査**: 行の追加（児童・地区役員・自治会役員・外部関係者・代表の地区）、班リストの編集、代表への地区追加、座席の段・列変更は、変更後の内容が端末へ保存でき次回解除できる場合だけ確定する。超過する場合は「端末に保存できる上限を超えるため、この変更を取り消しました」と通知し、画面と保存値を変更前のままにする。
- **E-12-02 保存前検証と拒否中の表示**: 自動保存・明示保存は、解除時と同じ受入検証に合格した値だけを書き込む。ロック中・未暗号化の役員データなど、もともと書き込まない保存は対象外とする。不合格時は保存値を変更せず、画面上部に「端末に保存できない内容があります（対象モード）。直前の変更を元に戻してください。」を表示し続ける。各モードで初めて不合格になったときは1回だけ通知する。表示中はページ離脱時に確認を求める。保存が成功すると表示を消す。アプリ更新・ブラウザ引き継ぎの作成は、保存できない内容がある場合にその旨を通知して中止する。
- **E-12-03 座席の段・列変更**: 縮小で範囲外になる割当て・自由記述がある場合は件数を示して確認する。取消時は元の段・列へ戻し、通知しない。承認時と範囲外が空席だけの場合は、範囲外の座席をすべて削除する。拡大・縮小により座席表の表示量上限を超える場合は通知して元の段・列へ戻す。長い地区名の自治会長・校外委員や、長い住所・氏名の免除世帯も保存・再解除できる。
- **E-12-04 旧版の保存値の修復**: 旧版で保存した範囲外の座席、座席表示量の超過、旗振りの展開量超過、4096文字超の旧項目名は、解除・起動時に修復して全モードを開き、「保存データの一部を修復して開きました」と修復内容を1回通知する。範囲外の座席は削除し、座席表示量の超過は4列×5段へ戻す。旗振りの超過値は下書きとして保持し、入力状態の案内を表示する。保存原本は次の保存（旧形式端末では解除時の形式移行）で修復後の内容になる。修復しても受け入れられない値は従来どおり拒否する。
- **E-12-05 解除失敗の表示・読めない平文**: パスワード・生体認証のいずれの解除でも、保存データの検証に失敗した場合は「保存データの検証に失敗しました」と表示し、パスワード誤り・認証失敗と区別する。未暗号化で起動して一部のモードの保存データを読めない場合は、そのモードだけ既定状態で起動して保存を停止し、上書きしない旨と、全消去または正しいデータの復元を案内する。他のモードは通常どおり開く。停止中は端末暗号化の設定を受け付けず全消去を案内する。停止中のモードの編集は保存されないため、ページ離脱時に確認を求める。アプリ更新は実行できる。引き継ぎの作成は、復元先のデータを既定状態で上書きしないよう、保存停止中である旨を示して中止する。自治会ファイルの読込（全体の置換）・引き継ぎ復元で当該モードを正しく書き込むと保存を再開する。
- **E-12-06 期間プリセット**: 前期・後期・通年のプリセットは手入力と同じ上限検査を通す（E-13-03 の休日の置換えを含む）。上限超過は下書きとして保持し、入力状態の案内を表示する。基準年は E-13-03 の年度とし、前期は4月6日〜9月30日、後期は10月1日〜翌年3月24日、通年は4月6日〜翌年3月24日とする。
- **E-12-07 自動生成の失敗**: 当番名簿が未設定のときの自動生成が上限超過などで失敗した場合は、通知してプレビューを更新し、名簿・下書きは変更しない。
- **E-12-08 記憶パスワードの非伝搬**: 地区・代表ファイルの読込・貼付は、ファイル内の記憶パスワードを採用しない。読込前に端末で記憶していたパスワードは維持する。地区ファイルの保存・共有内容には記憶パスワードを含めない。
- **E-12-09 他タブ更新**: 暗号化中、他のタブが地区・代表・自治会・家庭情報の保存データを更新した場合、自タブはロックし「別のタブで保存データが更新されました」と表示する（役員モードは解除画面、自治会・家庭情報モードは画面上部の案内）。他タブの更新が自タブの保存待機中に起きた場合も、自タブは古い内容で上書きせずロックする。再解除で最新の保存値を表示する。
- **E-12-10 復号前処理**: 8MiB 上限までの取込テキストを、`BEGIN_DATA:` 〜 `:END_DATA` の切出しを含めて入力長に比例する時間で処理する。
- **E-12-11 ゲスト引き継ぎの復元**: 役員の名簿データを含まない引き継ぎの復元では、地区・代表データを保持する旨を確認文に表示し、自治会・家庭情報だけを置き換える。
- **E-12-12 追加地区名の上限**: 代表の地区追加の地区名と、その引き継ぎ下書きは4096文字以下とする。超過時は追加せずエラー欄へ表示する。
- **E-12-13 学年の受入**: ファイル・貼付から取り込む地区・代表データでは、氏名等がすべて空の児童行を取り除き、残る児童の学年が `'1'`〜`'6'` でない場合は、該当児童の氏名と学年を示して読込を中止し既存状態を保持する。家庭情報ファイルの学年も1〜6年に限り（版1の空欄は1年とする）、違反時はパスワード再入力を求めず該当児童を示す。端末保存値と引き継ぎは従来の受入を維持する。
- **E-12-14 次年度児童名簿の仮行**: 「児童名簿を追加」は、氏名・ふりがな・住所・電話・班長が空で学区外でもない仮行を除いてから追記する。
- **E-12-15 地区共有の長文退避**: 地区カードの2000文字超のLINE・メール共有は、クリップボードへの退避に成功した場合だけ外部アプリを起動する。拒否・API不在時は失敗を通知する。代表の切出しコピーもAPI不在時は失敗を通知する。
- **E-12-16 出力日付**: 地区・自治会・代表・切出し・旗振りの出力ファイル名と出力日は、端末ローカル日付の `YYYY-MM-DD`（旗振りは `YYYYMMDD`）とする。
- **E-12-17 休日・特別枠の注記**: 休日の2列目以降、特別枠の3列目以降に含まれるカンマは注記の一部として保持し、上限検査も同じ注記で行う。

## E-13 出席初期チェックと期間プリセットの基準年（R-24）

- **E-13-01 会長の判定と新しい名簿の初期チェック**: 自治会役員の役職が、前後の空白を除いて「会長」「自治会長」「町内会長」「町会長」のいずれかと一致する行を会長とする。「副会長」「会長代行」「PTA会長」「副自治会長」「区長」など、これら以外の役職は会長としない。代表モードに、同じ地区名（前後の空白を除いて比較し、班は問わない）の代表名簿にも、名簿を置き換えるエントリ（自治会ファイルでは同名の全エントリ）の差替え前の名簿にも氏名のある自治会役員がいない状態で名簿を取り込むときは、氏名のある会長の行を出席とし、氏名のある会長がいなければ、名簿内で重複しない氏名のある最初の行を出席とする（最初の氏名のある行が重複行なら、その次の、重複しない氏名のある行）。氏名のある行がなければ誰も出席にしない。同じ内容（氏名・役職・電話・住所）の行が名簿内で重複して本人を特定できない行は出席にしない。氏名のある会長が重複行だけの場合も「氏名のある会長がいる」ものとして代替チェックを行わず、誰も出席にしない。比較元（差替え前の代表名簿と、名簿を置き換えるエントリの差替え前の名簿）が氏名のない空枠（年度更新後・初期状態の会長・副会長枠など）だけの場合は、照合する名簿がないものとして扱う。取り込む名簿は、役職だけの空枠でも、役職または氏名のある行があれば E-13-02 の名簿差替えとする（自治会ファイルは行の内容によらず名簿差替えとする。E-13-02）。その地区に残っていた出席の記録は使わず、この規則で作り直す。
- **E-13-02 名簿差替え時の出席チェック**: 地区・自治会データの集約（代表カードのファイル読込・マスター読込欄からの地区／自治会ファイル読込・貼付読込・タブ①自地区データの合算）で、取り込むデータに自治会役員名簿（役職または氏名のある行）があるとき、名簿を置き換えるエントリの出席を次のとおりとする。貼付読込の地区データは地区ファイルと、自治会データは自治会ファイルと同じ扱いとする（差替え前の名簿の代替元、置き換えるエントリ、同名エントリの作り直し、名簿のない取込の扱いを含む）。
	- **用語**
		- 名簿（取込の判定）: 役職または氏名のある行を1行以上持つ自治会役員名簿。役職・氏名とも前後の空白を除いて比べ、旧形式の氏名（`name`）も氏名に含める。氏名・役職が空白だけの行は数えない。代表名簿・座席候補のエントリを選ぶときの行数は、従来どおり氏名・役職の値がある行を数える（空白だけの値も数える）。
		- 代表名簿: 取込前に、同じ地区名（前後の空白を除いて比べる）のエントリのうち氏名または役職のある自治会役員の行数が最多のエントリの名簿。同数なら一覧で先のエントリの名簿とする。
		- 比較元: 差替え前の代表名簿とする。それに氏名のある行がなければ、地区ファイル・自地区の合算では名簿を置き換えるエントリの差替え前の名簿、自治会ファイルでは同名のエントリのうち一覧の順で最初に氏名のある行を持つエントリの名簿とする（代表名簿以外の比較元を代替の比較元という）。新しく加えるエントリ（同名・同班のエントリも仮エントリもない新しい班・新しい地区）には差替え前の名簿がなく、代替の比較元はない。
		- 置き換えるエントリ: 地区ファイル・自地区の合算では同じ地区名・班のエントリ、それがなければ先の自治会ファイル取込で作られた班・児童・校外委員のない同名の仮エントリ、それもなければ新しく加えるエントリとし、自治会ファイルでは同じ地区名の全エントリとする。地区ファイル・自地区の合算の置き換えるエントリ・仮エントリと、名簿のない取込の写し元は、従来どおり地区名の完全一致（前後の空白を含む）で選ぶ。代表名簿、自治会ファイルの対象、同名エントリの作り直しの対象は、前後の空白を除いた地区名で比べる。
		- 座席候補のエントリ: 前後の空白を除いた地区名ごとに、印刷対象のエントリのうち氏名または役職のある自治会役員の行数が最多のエントリ（同数なら一覧で先のエントリ）。印刷と座席候補の出席は、このエントリの出席による。
		- 旧版: SPEC-Q1・Q2 の適用前のアプリケーション。
	- **名簿を置き換えるエントリの出席**
		- 比較元に氏名のある行がある場合は、差替え前と同一の本人（氏名・役職・電話・住所が一致し、差替え前・後の名簿内でそれぞれ一意）の出席の有無を引き継ぐ。チェックのなかった本人はチェックなしのまま引き継ぐ。比較元で一致した本人について利用者が外したチェックは、会長でも戻さない。
		- 代替の比較元からは、チェックなし（外したチェックを含む）と会長の行のチェックだけを引き継ぎ、会長以外の本人のチェックは引き継がない（代表名簿でないエントリの値は出席セレクタで確認できず、旧版の行番号同期で別の本人に付いた値と区別できないため）。引き継がない本人は、差替え前に同一の本人がいない行と同じく扱う。
		- 差替え後の名簿内で同じ内容の行が重複して本人を特定できない行は出席にしない。氏名のない行は、取込のたびに出席なしとする（旧版で付いたチェックも引き継がない）。
		- それ以外で差替え前に同一の本人がいない行（一致なし、または差替え前の名簿で重複していた行）のうち、氏名のある会長の行を出席とする。比較元が代表名簿の場合、代表名簿にいない本人は、置き換えるエントリの差替え前の名簿で外していても（そのエントリが以前代表だったときに外したものを含む）一致しない行として扱い、氏名のある会長（差替え後の名簿内で重複する行を除く）なら出席とする。
		- 比較元（差替え前の代表名簿または代替の比較元）に氏名のある行がある差替えでは、先頭行などの代替チェックを行わない（比較元がなければ E-13-01 による）。
		- 自治会ファイルでは同名の全エントリに同じ結果を適用する。自治会ファイル（貼付した自治会データを含む）は、役職・氏名のある行がない名簿（空の名簿を含む）でも、従来どおり同じ地区名の全エントリの名簿を置き換え、出席はすべてなしとする（名簿を保護して写すのは、地区ファイル・自地区データだけの動作である）。
		- 他の地区の出席は変更しない。
	- **置き換えない同名エントリの作り直し**: 地区ファイル・自地区の合算で名簿を置き換えた場合、置き換えない同名エントリ（別班と、地区名の前後の空白だけが異なるエントリ）の出席は、従来の照合（印刷対象の切替など）と同じく本人単位で作り直す。
		- まず、氏名のない行、そのエントリの名簿内で重複する行、取込後の名簿で重複して本人を特定できない行は、出席なしとする。
		- それ以外の行は、差替え前の代表名簿と本人が一意に一致すればその出席とし、そうでなく取込後の名簿と本人が一意に一致すれば（取込で加わった会長など）取込で決めた出席とする（それぞれチェックのない本人はチェックなし。氏名のある行がない名簿とは照合しない）。どちらとも一致しない行は出席なしとする（旧版や出席セレクタの行番号同期で付いた値も残さない）。
		- これにより、取込で代表のエントリが入れ替わっても、印刷対象の選び方が変わっても、本人の出席は変わらない。
	- **名簿のない取込**: 取り込む地区ファイル・自地区データに自治会役員名簿がない場合は名簿差替えとせず、既存の同名エントリの名簿を保護して写す従来の動作を維持する（写し元は、同名のエントリのうち一覧の順で最初に名簿を持つエントリ）。
		- 写した名簿がそのエントリ自身の名簿なら、出席を変更せず、同名エントリの作り直しも行わない（名簿の行数が変わらないため、代表のエントリも入れ替わらない）。
		- 別のエントリの名簿を写した場合（新しく加えるエントリを含む）は、置き換えるエントリの出席は代表名簿（氏名のある行がなければ写し元。写し元は代替の比較元として扱う）の出席を本人単位で引き継ぎ、会長の自動チェックも代替チェックも行わない。このとき、代表のエントリ自身が写し元の短い名簿に置き換わって代表が入れ替わることがあるため、置き換えない同名エントリ（写し元を含む）は、名簿のある取込と同じく、差替え前の代表名簿と写した後の名簿で本人単位に作り直す。ただし、写した名簿の中の重複は写し元に元からあるものなので、取込後の名簿で重複する本人として出席なしにはしない（そのエントリの名簿内で重複する行は出席なし）。
		- 写す名簿がない場合は、置き換えるエントリ（新しく加えるエントリを含む）の出席をなしとし（残っていた値も消す）、同名の他のエントリは変更しない。
	- **氏名のない行の出席**: 名簿のある取込（自治会ファイルは名簿の有無によらない）と、別のエントリの名簿を写す名簿のない取込では、その地区の同名の全エントリに氏名のない行の出席が残らない（自エントリの名簿を写す名簿のない取込では出席を変更しない。写す名簿がない名簿のない取込では、置き換えるエントリの出席だけをなしとし、同名の他のエントリの値は変えない）。
	- **取込以外の操作の出席**: 出席は、地区詳細モーダルでの編集、印刷対象の切替、地区の削除では従来どおり行単位・本人単位で引き継ぎ、会長を自動でチェックしない。これらの操作の出席は、従来どおり代表名簿と照合する（座席は前述のとおり座席候補のエントリで照合する）。照合の対象は、代表名簿のエントリと地区名が完全に一致する（前後の空白を含む）エントリだけである。そのため、そのうち代表名簿でないエントリで代表名簿と本人が一致しない行の出席（取込で付いた会長のチェックを含む）は解除される。地区名の前後の空白だけが異なるエントリの出席は、これらの操作では変わらず、次の取込の作り直しまで残る。
	- **出席の表示・印刷・座席候補**: 出席の表示は同名の代表名簿の出席により、印刷と座席候補は印刷対象のエントリのうち氏名または役職のある自治会役員の行数が最多（同数なら一覧で先）のエントリの出席による（いずれも従来どおり）。取込で付ける出席は代表名簿・取込後の名簿と本人単位で決めるため、印刷対象の選び方で本人の出席は変わらない。
	- **出席セレクタの同期**: 出席セレクタでのチェックは、同じ地区名（前後の空白を除いて比べる。地区名が空なら同期しない）の他のエントリへ次のとおり同期する（E-03-06 の「同一地区」も同じ）。
		- 名簿（行の内容と並び）が操作したエントリと同じエントリ（名簿のないエントリどうしを含む）には、従来どおり同じ行番号へ同期する（重複行・行のない行番号を含む）。
		- 名簿の異なるエントリには、操作した行と内容（氏名・役職・電話・住所）が同じ行へ同期する（操作したエントリ・同期先の双方の名簿内で一意な場合に限り、同じ内容の空欄の枠を含む）。
		- 名簿の異なるエントリへの従来の行番号による同期は、別の本人や氏名のない枠を出席にするため廃止し、操作した行と内容の異なる行の出席は変更しない。
	- **旧版で保存された値**: 旧版の行番号同期で別の本人に付いて保存された値は区別できない。この値は、照合（印刷対象の切替・地区詳細モーダルでの保存・地区の削除。代表名簿のエントリと地区名が完全に一致するエントリに限る）と、名簿のある取込・別のエントリの名簿を写す名簿のない取込（名簿を置き換えたエントリの照合と、置き換えない同名エントリの作り直し）で、代表名簿と一致しなければ解除される。代表名簿に氏名のある行がなく代替の比較元と照合する取込では、代替の比較元から会長以外の本人のチェックを引き継がないため、この値のうち会長以外の行の `true` は持ち込まれない（`false` と会長の行の値は、旧版の同期で付いたものでも代替の比較元から引き継ぐ）。
	- **座席の再対応**: 座席を再対応するすべての操作（取込、地区詳細モーダルでの編集、印刷対象の切替（一括を含む）、地区の削除、外部関係者の行の削除など）では、自治会役員の座席を、所属（地区名・役職）と本人（氏名・役職・電話・住所）が同じ出席者へ引き継ぐ。
		- 引き継ぐのは、その本人が変更の前と後の座席候補のエントリの名簿の中でそれぞれ一意で、変更の前後とも出席者の中にちょうど1人いる場合に限る（行が移った本人の座席は新しい行へ移る）。それ以外は座席を解除する。
		- 変更前に別々の出席者（異なる参照）へ割り当てた座席どうしが、変更後に同じ出席者に当たる場合も、どちらの座席か決められないため、それらの座席を解除する（R-09）。同じ出席者に割り当てた複数の座席は、1つの割当てとして扱う。上の条件を満たせばそろって引き継ぎ、満たさない場合と、別の出席者に割り当てた座席と変更後に同じ出席者に当たる場合は、そろって解除する（同じ出席者の座席どうしは、一対一の規則で解除しない。旧版と同じ）。
		- このため、電話・住所だけが異なる同じ氏名・役職の会長には、取込で新たに出席になった場合も、その後の操作で座席候補のエントリが替わった場合も、旧会長の座席を引き継がない（R-09。地区詳細モーダルでその行を編集した場合は次のとおり）。
		- 地区詳細モーダルで座席候補のエントリの行を編集した場合は、編集前の行と編集後の行を対応させる。座席候補のエントリが替わらなければ、従来どおり対応する行へ写す（削除した行の座席は解除し、写し先の行が名簿内で重複していれば解除する）。座席候補のエントリが別のエントリに替わる場合は、編集前の本人と編集後の本人（編集後の名簿内で一意な場合）のうち、新しい座席候補のエントリにちょうど1人だけ出席している方へ引き継ぐ。両方が出席していれば、どちらの座席か決められないため解除する（R-09）。削除した行と、編集後の名簿で重複する行は、編集前の本人だけで照合する。
		- 座席候補のエントリの名簿内で重複する行の座席は、出席が残る場合も解除する（取り込んでいない地区を含む）。重複の判定は、座席候補のエントリが替わらないモーダル編集では編集後の名簿だけで行い、それ以外の操作では変更前と変更後の座席候補のエントリの名簿で行う。
		- 作り直しで出席から外れた本人の座席も解除する。座席候補のエントリの地区名（前後の空白を含む）が変更の前後で変わると、所属が変わるため座席を解除する。校外役員・外部関係者の座席は、従来どおり所属と表示名で照合する。自由入力・設備の座席は、従来どおり再対応の対象にせず、そのまま残す。
	- **座席の旧版との差**: 旧版は、自治会役員の座席も所属と表示名だけで照合していた（取込では、出席を代表名簿と照合し直したうえで照合していた）。これと比べて、次の点が異なる。
		- (1) 所属と氏名が同じでも、地区名・役職・電話・住所のいずれかが異なる人を区別する（所属の文字列が地区名と役職の分かれ方の違いで偶然一致する場合を含む）。地区詳細モーダルでの編集を除き、電話・住所の異なる同名の会長へ座席が移ることはない。氏名・役職が同じで電話の異なる2人が出席していても、そのことだけを理由には座席を解除しない（旧版は解除した）。
		- (2) 自治会役員の識別子と、校外役員・外部関係者の識別子は互いに一致しない。このため、所属と表示名が同じ自治会役員と外部関係者・校外役員がいても、そのことだけを理由には座席を解除しない（旧版は解除した）。
		- (3) すべての操作で、判定に代表名簿ではなく、変更前後の座席候補のエントリの名簿と変更後の出席を使う。代表名簿にいない本人や代表名簿で重複する本人でも、変更前後の座席候補のエントリで一意な同じ本人が出席していれば引き継ぐ。座席候補のエントリで重複する行の座席は、代表名簿で一意でも、また出席が残っていても解除する（地区名が代表名簿のエントリと前後の空白だけ異なる座席候補のエントリで、旧版が残していた場合を含む）。
		- (4) 地区詳細モーダルで座席候補のエントリが替わる編集では、編集前と編集後の本人のうち新しい座席候補のエントリに出席している方へ引き継ぎ、両方が出席していれば解除する。変更前に別々の出席者へ割り当てた座席どうしが同じ出席者に当たる場合は解除する（旧版の照合は1対1で、この状態は起きなかった）。変更前の座席候補のエントリで重複していた行の座席は、座席候補が替わる編集では解除する（旧版は、所属と表示名が同じ出席者が1人なら引き継いでいた）。旧版は編集前の所属と表示名で照合したため、氏名・役職を直した本人へは引き継がず、所属と表示名が編集前と同じ出席者がいれば、電話・住所が異なってもその出席者へ引き継いでいた。
		- (1)〜(3) は、同じ本人を確かめられる場合だけ引き継ぐ R-09 の扱いによる。(4) は、モーダルの編集では行の対応から編集後の本人も分かることと、編集前後の本人がともに出席すると本人を決められないことによる。
	- **取込の失敗時**: ファイル・貼付の取込が検証・保存に失敗した場合、および自地区データの合算が検証に失敗した場合は、出席を含めて変更しない（合算後の保存失敗は E-12-02 の表示による）。
- **E-13-03 期間プリセットの年度**: 操作日の月が1〜3月なら前年、4〜12月なら当年を年度の開始年とし、前期・後期・通年のプリセットに使う。例えば2027年2月の操作では、前期は2026年4月6日〜9月30日、後期は2026年10月1日〜2027年3月24日、通年は2026年4月6日〜2027年3月24日となる。3月31日は前年、4月1日は当年が基準となる。休日欄が自動生成した祝日一覧のまま（空でなく、休日の下書きがなく、設定中の開始日の年または当年、開始日がなければ当年・前年・翌年から生成した一覧と一致）なら、プリセットの年度の祝日一覧（開始年〜翌年。祝日の自動計算は2000〜2099年が対象のため、年度2099は2099年分だけとし、年度が2000〜2099年の範囲外なら休日欄を置き換えない）に置き換え、期間と一括して同じ上限検査を通す。上限超過時は期間・休日とも有効値を変えず、置き換えた一覧を含めて下書きとして保持する。空の休日欄や編集した休日欄、休日の下書きは変更しない。旗振り設定がないときの初期期間・初期休日と、役員データの有無の判定で既定とみなす期間・休日は従来どおりとする。
- **E-13-04 年度更新の旗振り下書き**: 年度更新は旗振りの下書きを破棄する（SPEC-Q3 の現行仕様を維持）。
