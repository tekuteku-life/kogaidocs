# UIテスト拡充・不具合切り分け記録

実施日は2026年10月21日である。対象は `docs/system_design.md`、`docs/development_process.md`、`index.html`、CSS、全11 JavaScriptモジュール、Service Worker、manifest、および既存の単体・結合・システムテストである。独立レビューはCodexサブエージェントが担当する。

## 基準と手順

初回の `npm test` は実行制限内ではChromiumのソケット・子プロセス起動が拒否され、実行制限外では265件合格した。これは環境起因であり、アプリの正常性を確認する根拠には制限外の実行結果を用いる。初回カバレッジは全11モジュールの行100%であるが、`rep.js` の分岐94.96%は既存基準95%未達であった。

従来のUIテストは9シナリオであり、主にグローバル関数の直接呼出しで検査していた。`--dump-dom` と仮想時間だけでは非同期暗号化の完了を保証できず、起動時例外の捕捉開始も遅かった。今回のテストはChrome DevTools Protocolのpipe通信を用い、実DOMへの入力・change、ネイティブのクリック・Enter/Escape、暗号化完了、実再読み込みを待つ。起動時例外と未処理Promise拒否も回収する。各シナリオのプロファイルは独立し、終了時に破棄する。

実ブラウザは仕様でサポートする `file://` 起動である。OSの印刷ダイアログ・実プリンター・OS共有先・生体認証器は自動検証の対象外である。印刷・共有・クリップボードのOS境界のみを置き換え、呼出時点の帳票DOM・タイトル・暗号文を検証する。15分のタイマーは同じ期限のコールバックを制御時計で進めて検査する。WebAuthnの分岐は既存単体テストで補完する。HTTP配信のService Worker実動作とオフライン再起動は、このfile起動の検証結果から合格と推定しない。

## 切り分け

テスト側の修正は、実DOMのセレクター誤り、閉じたdetailsへの操作、班ごとのソート前提、フォームEnterのネイティブkeypress、URL更新によるテストパラメーター消失である。これらは期待するアプリ動作を緩和せず是正した。

実装側で再現する不具合は以下である。修正前のRedを保持したまま独立したGate 2レビューを受け、設計・Gate 1を経て本線修正へ進む。

1. 転入者の暗号化移行と全消去対象漏れ。
2. ロック時の旗振り・外部関係者・座席・詳細下書き・入力欄・パスワードの残留、および解除後のパスワード残留。
3. 初回暗号化完了後の自動ロックタイマー未開始。
4. 旗振り独自休日のDOM復元漏れ、JSON読込時の未捕捉例外・不正型・再選択不可。
5. 世帯キーをインラインJavaScriptへ埋め込むことによる引用符破損とコード注入。
6. 参加者削除による配列インデックス参照ずれ、および名簿編集後の出席者・座席候補の更新漏れ。
7. 自治会名札の氏名・かな・役職の引数順誤り。
8. 地区の貼付復元ボタンに対応する関数の欠落。
9. 代表の一般ファイル選択で転入データを地区データとして取り込む振分漏れ。
10. 自治会の暗号化コピーにおける確認パスワード不一致検査漏れ。

代表年度更新は実装・確認文言・既存テストの契約である「集約地区クリア、外部組織枠保持」を採用する。設計書中の「全地区進級」という記載を是正する。旗振りJSONのmembersは地区児童名簿を元とする既存仕様を維持し、読込時の設定と名簿の責務を明記する。

## 手戻りとレビュー

初回のテスト完成後はUI75件中25件が実装不具合で失敗した。Gate 1は `review36_ui_design.md`、Gate 2は `review37_ui_tests.md` でPASSとなり、本線修正へ進んだ。暗号化失敗時の部分書込み、ロック後の非同期処理による復活、同一地区の自治会代表切替、印刷CSS等も横展開して設計・再現テストを補強した。

全343件の合格後にも独立監査で不足が見つかったため完了扱いにせず、Stage 2・4へ戻った。自治会役員の通常編集時の出欠・座席参照保全、空の旗振りJSON拒否、地区内旗振り・座席寸法等のネストしたスキーマ検証、代表マスターの貼付復元・統合ファイル入口の振分、および配列形式の休日の正規化を追加した。それぞれのRedを実行した後、再設計を `review38_ui_rework_design.md`、再テストレビューを `review39_ui_rework_tests.md` で受診した。

再検証中に既存テストで見つかった取込通知の班名欠落は実装側を是正した。検証済みデータを返す `parseTxtContent` のモック2件は、実際の検証・正規化契約へ合わせた。暗号化済みロック状態、座席セル形式、確認パスワード欄に関する古いフィクスチャも実際の契約に合わせ、期待する機能・保護条件を緩和していない。

続く最終監査では、旧形式の単一 `officer` の外側しか検証しておらず、不正な班オブジェクトにより状態置換後の描画が失敗する指摘を受けた。再びStage 2・4へ戻り、地区・代表双方の不正型拒否と状態保持、正常な旧形式の実DOM復元をテストへ追加した。修正前はUI5件中2件と追加単体テストが失敗し、正常旧形式のUIは合格した。旧子氏名・かな・子ふりがなも横展開し、`review40_ui_legacy_design.md` と `review41_ui_legacy_tests.md` のPASS後、共通行スキーマへ検証を統一した。
