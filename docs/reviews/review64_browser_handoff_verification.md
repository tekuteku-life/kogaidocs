# 旗振り統合・LINE内ブラウザ引き継ぎの最終検証

対象は `feature/hata-full-integration`、アプリケーション2.9.0である。初回要件は [review61](review61_hata_integration_design.md)、追加要件は [review63](review63_browser_handoff_design.md) に示す。review62の729件の結果は追加要件前の記録である。

## 最終動作

- 開発元が同一であるというユーザーの指示に従い、今回追加した第三者ライセンス通知を削除した。
- ハタフロットJSONは読込専用とした。保存ボタン、イベント、`exportHataOfficialJson` を削除した。全旗振り設定は地区の暗号化エクスポートで保存できる。
- LINE型UAに警告を表示し、同一アプリのモード付きURLへ `openExternalBrowser=1` を付けたリンクと、LINEメニューから開く案内を提供した。元URLの機微なquery/hash、個人情報、暗号文、鍵は移動URLに含めない。
- 地区・代表・自治会・未完了転入者、全旗振り設定、代表の未確定名簿編集と旧行index、貼付欄等の下書きを専用暗号化データで引き継ぐ。ファイル保存またはコピー後、移動先でファイル/貼付とパスワードから復元する。自動移動・自動復元を行う方式ではない。
- パスワード、端末暗号化設定、生体認証、未読込ファイルを引き継がない。移動先に端末暗号化がある場合はその方式を維持する。

## 具体的な検証

`browser-handoff.test.js` はLINE/非LINE判定、URLからの秘密情報除去、未完了の転入者と全旗振り設定の保持、パスワード除外、不正モデル・旧行index拒否を確認する。実WebCryptoで作成・復号し、誤鍵・不正型・置換取消、全モード書込み失敗のrollback、暗号化維持、暗号化完了後の取消による書込み0、ロック拒否を確認した。未確定名簿を移動先で保存したときの座席参照も検証した。

`headless-browser-handoff.test.js` は実ChromiumでLINE警告、未完了フォーム・未確定名簿編集を含む実暗号化ファイル出力/コピー、独立保存領域相当の消去後のファイル復元と再起動、貼付復元、誤鍵・置換取消・コピー拒否、Escape・ロック後の遅い処理の無効化を確認した。375pxで警告と操作の到達性も確認した。

## 既存認証試験の失敗切り分け

途中の全体検証は744件中743件合格であり、「代表データの認証タグ改ざん後のロック画面」が失敗した。単独反復と変更前HEAD `5eaec3d` を一時展開したコードでも再現した。失敗時は再起動直後の `file://` 保存領域から認証メタデータと検査用の暗号文マーカー自体が消えていた。アプリが改ざんデータを受け入れた結果ではない。

開始URLのモード指定では解消しなかった。固定HTTPSオリジンのCDP応答も試みたが、この実行環境ではナビゲーションがタイムアウトしたため採用しなかった。最終的に認証タグ試験の4ケースに限ってChromiumの `--allow-file-access-from-files` を明示し、再起動前後の暗号文保持をassertした。代表ケース8回連続と4モード全件が合格した。アプリ本体の認証処理は変更していない。設定なしのfile保存領域の永続性を保証するものではない。

座席参照の先行試験では印刷対象のフラグを省いたfixtureが失敗した。実UIの前提どおり原本と下書きに `selectedForPrint: true` を指定し、残存役員への参照保持と削除役員の参照解除を確認した。

## 検証の限界とレビュー

ChromiumとNodeの検証であり、LINEアプリからSafari/Chromeへ移動するOS動作、実ファイル配送、iPhone実機でのホーム画面追加・独立起動、本番TLS・HTTPヘッダー・更新配信は未検証である。UA検知はLINEがUAを変更・抑制した場合に完全ではない。引き継ぎは4MiBのJSON構造上限と8MiBの入力ファイル上限に従う。

差分、状態収集、型検証、原子的保存、ロックと古い非同期処理の経路を自己点検した。独立サブエージェントによるレビューは実施しておらず、独立レビューのPASSは主張しない。ユーザーは作業完了後のコミット・pushを明示的に指示している。公開の実行結果はチャットの完了報告とリモート追跡参照で確認する。
