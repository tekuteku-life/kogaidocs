# UI操作・保存データ読み込みの再監査

開始点は `test/ui-workflow-audit` の `7ef1830`（2.9.1）である。過去の765件/139件は比較用の記録であり、本監査の実行結果と区別する。既存の仕様・保存/復号/取込/描画/再保存の全入口、UIイベントと実アサーションを照合する。

## 入力と信頼境界

| 入口 | 検証から利用まで | 追加確認 |
| --- | --- | --- |
| 地区・代表・自治会の暗号化提出ファイル/貼付 | readImportFile / parseTxtContent → validateImportData → 正規化 → 描画/保存 | 改ざん、型、予約キー、旧名義、パスワード非伝搬、既存値保持は既存試験を再実行する。新しい旗振り書式・免除属性・下書きを追加攻撃対象とする。 |
| 公式旗振りJSON | validateHataConfig → 日付展開検査 → 描画/保存 | 文字列形式の名簿、連絡文、書式による処理/出力増幅の上限を確認する。 |
| 平文/暗号化LocalStorage | 全4モデル復号 → validateStoredData → 正規化 → 一括確定 | 下書きの攻撃文字列と処理上限を再起動・解除から検証する。認証済み暗号文も信頼しない。 |
| ブラウザ引き継ぎ | validateBrowserHandoff → 4モデルの同じ検証 → 原子的保存 → 描画/下書き復元 | 新設の免除属性・書式と未完成下書きを復元後の実操作まで検証する。 |

## 再点検での不足

- XSSの既存試験は旗振りタイトル・メタ情報・担当者・注記、旧免除キーを扱うが、新しい `data-member-name`、指定書式を反映した名簿、`inputDrafts` を再起動から修正して出力する経路は直接アサートしていない。
- JSONの4MiB、ファイルの8MiB、配列10000件、日付3660日の制限は存在する。一方で文字列の改行で作る当番名簿、テンプレート反映、同じ担当者・注記を多数の日付へ反復する出力は別の増幅境界である。
- 書式は置換を順番に繰り返すため、児童の入力値内に後続の書式トークンがあると、その値まで再解釈する。この処理の非再解釈と出力量を先行試験する。
- 通常ファイル取込で保存容量不足になった場合のUIと原本の整合性は、引き継ぎの保存失敗試験とは別である。失敗時の実測を追加し、製品・試験側の問題を切り分ける。

## 先行設計

書式トークンは単一パスで解釈し、置換した児童データを再解釈しない。名簿は文字列でも配列と同じ10000担当者以下とし、表示名・日付指定行・書式は4096文字以下とする。書式反映の結果と生成シフトの反復表示値はUTF-8で1MiB以下とし、出力構築前に制限する。長い未完成の生入力は評価・展開しない。受入検証を全入口で共有し、不正な候補を本状態へ確定しない。UIの明示反映・生成・出力で上限に達した場合は通知し、元の名簿・設定・表示を維持する。

本記録は実装担当の監査である。独立サブエージェントのGate1〜3、実iPhone/LINE、TLS/HTTPヘッダー、OS認証器・共有・印刷・SW更新は別の境界として残す。

SEC-20の先行単体試験5件はすべて修正前に失敗した。書式トークンの二次解釈、10001担当者の文字列名簿受理、長大書式、UTF-8出力量、長期間の反復表示量をそれぞれ検出した。新しい上限で通常編集を不正保存にしないため、members/formatも既存の下書き機構へ加える。表示量は最長担当者と最長注記による保守的な上限であり、実際の出力サイズの厳密な予測ではない。

## SEC-21 保存失敗時の取込状態

通常取込の先行UI試験4件（地区・代表・自治会・公式JSON）は、保存Promiseまで待機するよう試験側を補正した後もすべて失敗した。地区・公式JSONは保存失敗時にも本状態が候補へ置換される。代表・自治会には保存をawaitせず成功を通知する経路もある。これをデータ保全・可用性の問題として是正する。XSSによる外部漏洩とは区別する。

commitImportedModel は共有の検証・セッション世代・ストレージ排他を通し、保存完了後に候補を返す。各取込はこの戻り値を本状態へ採用してから描画する。代表の地区追加・自治会統合と座席再対応は、対象モデルを明示した複製上で計算する。地区/代表の転入統合も複製上で全員分の確認を済ませてから保存する。平文保存には記憶パスワードを含めない。

SEC-20の横展開では、班名を各児童へ継承する処理、班選択肢×児童/役員行、参加者選択肢×座席数にも増幅経路がある。読み込みフィールドの短文を4096文字へ制限し、班選択肢は4MiB、全候補参加者を配置した座席選択肢は16MiBの保守的な見積もりで受入前に拒否する。短文フォームにもmaxlengthを付ける。これらの先行単体試験も修正前に失敗した。

SEC-21の確定時には、同じ排他区間でセッション世代を進め、取込中に待機した古い自動保存による再上書きを拒否する。代表の複数ファイルは自分で正常確定した後だけ次のファイルの世代を更新する。失敗したファイルを除き成功件数を通知する既存の部分成功契約は維持する。

試験側では、非同期統合の実Promise待機と、更新後の代表モデルを参照するよう修正した。CommonJSでグローバルへ代入したモデルとstate.js内部の参照が分離する問題も発見し、Nodeの場合だけ共有アクセサーへ統一した。実ブラウザの状態共有と同じ条件で保存を検証するための是正である。

保存先を先に確定する是正の再点検で、保存完了直後から呼出元の状態採用までの間にロックすると、遅い継続が個人情報を戻し得ることも実UIで再現した。保存結果はmodelと確定世代の組として返し、adoptImportedModelで採用の直前に世代・解除状態を再検証する。複数ファイルも現在世代を無条件取得せず、自分の成功による世代増分を照合する。途中の全体/UI一式は最終結果とはせず、修正後に再実行する。

さらに、復号完了後に別関数へ委譲する代表/自治会/転入取込では、開始時の世代を引き継ぐ。委譲先が現在世代を取り直すと、直前の全消去を新しい通常セッションと誤認して旧平文を再保存することを先行単体試験で再現した。保存直後のロックとの競合は先行UI試験で再現し、どちらも採用/委譲の境界で拒否する。

## 確認方式と残る境界

既存UIの4モードCRUD・並替/削除取消、代表の未確定編集と座席同定、年度更新、全12帳票、パスワード・暗号化/ロック・消去、PWA案内・レスポンシブ配置を追跡表と実アサーションへ照合した。追加した正常/境界/異常系は新しい書式・下書き・免除属性、読み込み展開量、保存失敗と非同期の採用/委譲境界である。関数名や単体網羅率だけをUI網羅の根拠にはしない。

クリックは可視性・被覆を判定したCDPマウス入力、キーはCDP入力である。文字入力はDOMのvalueとinput/changeイベント、ファイル選択はDataTransferを用いる。印刷/ダウンロード/クリップボード/confirmにはAPI代替を含む。暗号化と復号には実WebCryptoを用い、通信監視は陽性対照を確認する。

新しい旗振りの攻撃文字列について、DOM生成・イベント実行・秘密値の外部要求は観測していない。これを全ての未知の脆弱性が存在しない証明とはしない。実iPhoneのホーム画面追加・縦横回転/ソフトウェアキーボード、LINEからSafari等へのOS移動とファイル配送、安全な実HTTPS配信・HTTPヘッダー・SW更新、OS認証器・共有・印刷は未検証である。独立Gate1〜3も未実施であり、本記録は実装担当の再監査と試験結果である。

## 指摘の分類と是正結果

| 識別子 | 分類・成立条件・影響 | 是正と根拠 |
| --- | --- | --- |
| SEC-20 | 中: 受領者が作成元とパスワードを共有した保存ファイル、公式JSON、保存領域の内容を読み込む場合である。小さい入力から名簿・テンプレート・選択肢・日付行を増幅でき、処理停止や大量メモリ消費につながる。文字列内のトークン再解釈は表示内容の改変も起こす。 | 単一パス置換、結合前の行長・総UTF-8量、文字列行数、共通の画面展開見積もり、生成/描画の追加検査で制限した。先行単体の不合格、修正後の境界値と実ファイル/貼付/保存読込UIで確認した。 |
| SEC-21 | 中: 取込中の保存容量不足やロック/全消去が条件となる。元の状態と保存値の不一致、失敗の成功通知、古い保存/取込の継続による消去・ロック後の個人情報復活につながる。 | 候補保存後の採用、同じ排他区間での世代更新、採用直前の照合、委譲先への開始世代の引き継ぎで是正した。保存失敗は9経路×2保存方式、保存後のロックは実UI、旧自動保存と全消去後の委譲拒否は実暗号と単体試験で確認した。 |

XSS/任意コード実行や秘密情報の外部送信をSEC-20/21の再現結果から推定していない。確認したデータ保全・可用性・ロック後の表示機密性の問題と、追加XSS試験の不発生結果を区別する。
