**比較元**: main `601673d`、review43〜review54<br>
**対象**: 全本番JS 12モジュール、HTML/CSS、Service Worker、全取込・保存復元・印刷・共有・年度更新経路

## 方法と過去評価の追跡

過去review43のSEC-01〜17とreview44〜54の設計・テスト・手戻り・最終判定を読み、現在の防御と実アサーションを再確認した。過去記録の621件/97件を今回の実行結果として扱わない。脅威主体は、提出者・ファイルを差し替える第三者・ローカル保存を書き換える別コンテキストである。保護資産は児童・家庭・役員の個人情報、復号鍵・パスワードと既存作業データである。

信頼境界は、ファイル/貼付/公式JSON/平文保存/暗号化保存→復号→構造検証→正規化→本状態→DOM/印刷/保存/共有である。認証済み暗号文を安全なモデルと同一視しない。別タブ・待機保存・全消去・更新・ロックも境界に含める。

## SEC-18: 年度更新後の旧別名・余剰個人情報再出力

**重大度**: 中。**分類**: 情報漏洩。**成立条件**: 旧形式または余剰の個人項目を含む正規暗号化データを読み込み、年度更新後のファイルを次年度役員へ渡す場合である。

自治会はname/kana/contact、代表外部関係者はkana/address/tel/email/note等が消去されない。自治会のgetFullNameは空の分割氏名から旧nameへ戻るため、年度更新後の帳票にも旧氏名が出る。これはXSSの成立を必要としない漏洩である。

独立監査で実WebCryptoのencryptPayload→loadNeighborTxt→runNeighborYearUpdate→exportNeighborTxt→parseTxtContentと、代表の年度更新→出力→復号により残存を実証した。過去の年度更新試験には旧name/kanaや余剰個人項目を含むfixtureがなかった。

是正は、保持する組織項目だけを許可して行を再構築する方式である。自治会はrole、代表はcategory/org/roleを保持し、正式個人項目を空にする。旧別名・任意項目をコピーしない。確認取消は原本を保持する。外部仕様E-06-04、内部仕様I-04に定義する。

## SEC-19: 単独不正日付の受入と描画後の部分置換

**重大度**: 中。**分類**: 改竄・可用性。**成立条件**: 不正な単独旗振り開始日等を含む暗号化地区を読み込む場合である。

validateDateExpansionは片側が空なら早期returnし、startDate:'bad'を通す。loadDistrictTxtがcurrentDistrictと地区名DOMを置換してから、renderHataCardの自動祝日生成で例外になる。失敗通知が出ても旧状態へ戻らない。保存復元も同じ受入境界に依存する。上限年9999の翌年計算も同種の描画失敗につながる。

是正は、空でない日付端点を個別にISO実在日検証し、その後で両側の順序・日数を検証する方式である。自動祝日生成は開始年2000〜2099に制限し、翌年も2099までとする。範囲外の有効日付は受入れて休日を空へ補完し、利用者が明示した休日と空文字は保持する。これは法改正・特例日の正確性保証ではない。ファイル・貼付・公式JSON・平文/暗号化保存復元で状態確定前に適用する。外部仕様E-09-02/03、内部仕様I-03に定義する。

## 追加する検証と合否基準

- SEC-18は現行・旧形式・余剰項目を実暗号化取込し、取消時保持、実行後保存・再読込・印刷・再暗号化出力の非残存を確認する。
- SEC-19は不正文字列、非実在日、単独start/end、空の下書き、9999年を確認する。拒否時に状態・DOM・保存原本を保持する。
- 取込由来の画像/CSS/イベント/フォーム風文字列を保存・実再読込・印刷へ通す。対象ページのCDP要求に攻撃URL・canaryがないことと観測のpositive controlを検査する。
- 公式JSONの悪意文字列、PTA帳票の非開示、名札4面/回転、封筒12面の境界、旗振り均等割当をトレーサビリティの不足として補う。

設計Gate 1、テストGate 2、本線修正、全回帰、最終Gate 3の順で記録する。是正・実行前に合格とは判定しない。

## 残余リスク・未検証境界

暗号化は提出本文を保護する。ファイル名・平文ヘッダーには地区/班/日付、転入ファイル名には児童の姓が含まれ得る。利用者が選んだ未暗号化端末保存は平文である。悪意ある拡張機能、OS侵害、利用者自身の誤送信、同一originで任意コードを実行できる別アプリからの直接アクセスまで隔離する設計ではない。

meta CSPのframe-ancestorsは実配信ヘッダーの代替ではない。TLS・HTTPヘッダー・公開静的資産の配信契約、実OS認証器、共有先、実印刷、実オフライン更新は未検証である。filtered responseのSet-Cookie非公開という制約を、JSのヘッダー検査だけで解決したとは扱わない。

file起動のCDP要求観測は対象ページの試験入力・操作の検証であり、HTTP同origin配信や全ブラウザプロセスの漏洩不存在を保証しない。JavaScriptの所有生鍵バッファのゼロ化も、内部コピーやGC領域の消去保証ではない。
