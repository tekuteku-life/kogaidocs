## 2. 脅威モデル・入出力台帳の差分

保護対象・攻撃者能力・信頼境界は [review71](review71_security_assessment.md) 第1節を継承する。今回は次の不変条件を追加で検査した。

- **保存値の復元可能性**: 通常保存（`saveStorageData`）で書いた値が、次回解除時の全キー一括検証（`activateStorageKey` → `validateStoredData`）を常に満たすこと。満たさない値を1件でも保存すると、正しいパスワードでも全4モードが開けなくなる（可用性の喪失）。
- **取込値の信頼範囲**: 外部ファイルに含まれる端末ローカル設定（記憶パスワード）を採用しないこと。
- **他タブとの整合**: 暗号化中に他タブが書いた有効な暗号文を、自タブの古いメモリで上書きしないこと。
- **復号前入力の計算量**: パスワード不要で到達する取込前処理が入力長に対し線形であること。

### 3.1 多層防御の残余（今回は是正対象外）

- **R-SEC-A（`style-src 'unsafe-inline'`・Trusted Types 未導入）**: 現在の描画は `esc()` と固定イベント登録で防御している。インライン `style` 属性を広く使用しているため、CSP強化は描画部の全面改修を要する。今回の改修範囲外とし、将来のエスケープ漏れへの第2層は未整備であることを明記する。
- **R-SEC-B（`hata.inputDrafts` の値長）**: 下書きは上限超過の入力を保全する目的で長さを制限しない。構造全体4MiBの検査と、SEC-30 の保存前検証により、解除不能な値は保存されない。
- **R-SEC-C（未暗号化時の他タブ上書き）**: SEC-34 の是正は暗号化中の役員データを対象とする。未暗号化のゲスト（自治会・家庭情報）データの他タブ競合は従来どおり最後の書込みが有効となる。
- Webコードの制御外（実配信のHTTPS/TLS・`frame-ancestors`/HSTS 等のHTTPヘッダー、OSのスクリーンショット・クリップボード履歴、ブラウザ拡張、実機WebAuthn認証器、印刷スプール、JavaScript文字列のGC後残存）は [review71](review71_security_assessment.md) 第3節と同じく未検証境界とする。

### 4.1 仕様確認事項（今回は変更しない）

- **SPEC-Q1（会長の初期チェック）**: `upsertRepDistrict`・`mergeNeighborDataIntoRep` は「役職に『会長』を含む」人を初期チェックする（コードコメントで明示）。副会長・会長代行も対象となる。E-03-06「会長役職の自動初期チェック」の範囲について利用者の判断を要する。既存テスト `rep.test.js:46` の名称が意図と異なるため、実際の挙動（部分一致）を明記した名称・assertion へ修正する。
- **SPEC-Q2（名簿差替え時の出席チェック）**: `reconcileSeatState` は名簿差替え時に本人一致の出席チェックだけを残し、新会長の初期チェックを適用しない。仕様判断を要するため変更しない。

## 6. 判定

SEC-30〜35 および QA-01〜11 を是正対象とする（SEC-36 は取下げ、QA-11 へ再分類）。SEC-30 は利用者の通常操作だけで成立し、全データの可用性を失うため最優先とする。仕様確認事項 SPEC-Q1〜Q4 と残余 R-SEC-A〜D は記録にとどめ、本改修で変更しない。是正設計の詳細は第7節と [内部仕様書 I-12](../internal_design.md) による。

2回目の Gate 1（[review79](review79_design_gate1.md)）を受け、修復付き検証と厳格検証の分離、`name`・`childName` の条件付き上限、配列形式の旗振り値の文字列化、修復の通知と形式移行時の扱い、キー単位の書込停止、取込・引き継ぎでの外部更新照合、排他区間外での通知、家庭情報の学年違反文言を I-12 へ追加した。

- **SPEC-Q4（期間プリセットの基準年）**: 現行どおり暦年を基準とし、1〜3月に「後期」を押すと当年10月〜翌年3月になる。年度（4月始まり）基準への変更は利用者の判断を要する。
- **R-SEC-D（地区の描画予算超過の修復）**: 旧版で保存済みの地区の描画予算超過（行数×班選択肢）は、行の削除を伴うため自動修復しない。I-12-01 により新規発生は防ぐ。
