## 環境と主張の範囲

実ChromiumでDOM・CSS・クリック/キー・ファイル入力・実WebCrypto・再読み込みを検証する。ファイル選択はDataTransfer、ダウンロード・印刷・クリップボード・confirmはハーネスによる代替を含む。異常系では保存APIやPromiseの待機点を制御し、UIイベントから呼び出した実際のPromiseと対象状態を待つ。

LINEアプリから外部ブラウザへのOS移動、iPhoneインストール、OS認証器・ファイル配送・印刷、実HTTPS/TLS・HTTPヘッダー・Service Worker更新はこのUI試験だけでは保証しない。fileオリジンの保存保持にはChromiumの明示設定を用いる場合がある。独立レビューは別ゲートであり、自己監査を独立レビューのPASSとはしない。

## 再現と追加設計

初回UI基準実行は121/121件成功である。追加試験で地区追加のフォーカスと不正期間の保存を製品問題として再現した。休日・特別枠にも同じ保存経路があるため、4項目の未完成入力を inputDrafts に分離する。未完成文字列を入力のたびに拒否する方式では日付を手入力できないため採用しない。

保存失敗の比較前に通常自動保存が完了していなかった試験は待機を修正した。ChromiumのTab折返しは一時的にBODYを返すため、背景の操作要素に移らず次のTabでdialogへ戻ることを確認する。これらは製品障害として扱わない。

追加要求に従い、当番名簿へ書式フォームを移す。既存トークンと重複排除設定は維持し、変更だけでは手編集名簿を上書きしない。旧連携欄・名簿プレビュー・コピー処理を削除し、幅375/768/1280pxの配置と明示反映・取消を検査する。シフトプレビューは確認・印刷に必要であり維持する。

旧書式を当番名簿へ適用する追加要求の横展開で、免除候補が児童世帯だけを参照し、独自書式・手入力の担当者と一致しない問題を追加再現した。候補を実際の当番名簿へ変更し、従来の住所数字_苗字キーと表示名の両方を選択解除できるようにする。児童追加/編集の試験は、明示反映してから候補を検査する契約へ更新する。

途中の全体実行は764/764件成功であったが、免除修正と実行が重なったため最終結果として採用しない。最終ソースを固定した後に全体実行とUI一式をやり直す。
