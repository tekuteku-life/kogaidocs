# 長文復旧・共有失敗・次年度児童追加の設計およびテスト記録

**対象**: `fix/security-assessment-hardening`、2.11.1 → 2.12.0
**実施日**: 2026年11月18日

## 要求と根本原因

- 旗振りメタ文字列の4096文字制約が読込側へ追加された一方、複数行入力と保存側には同じ採用条件がなかった。4097文字の保存に成功しても、ロック後の全モード解除が失敗する状態であった。
- 地区切り出しの長文共有はクリップボード例外を無視して外部起動を続け、データを渡せていないのに成功を返していた。
- 通常の地区ファイル読込は全地区を置換するため、先に取り込んだ次年度役員へ児童だけを追加できなかった。児童省略・自治会配列ありの役員ファイルを自治会と誤判定する経路もあった。

## 設計判断と自己レビュー

- 新規の表示メタ長文と旧保存値は既存の `inputDrafts` へ全文を分離する。既存の構造容量制約と認証・世代検証は維持する。保存形式や暗号方式は変更しない。
- 表示メタ8項目の入力・保存・復元を共通の対象表へそろえる。下書きに不正値が残る間はシフト出力を停止する。型不正や未知キーを長文移行に便乗して許可しない。
- 共有拒否は既存のエラー処理へ伝播する。API不在時はファイル保存を案内し、ロック後の通知を抑止する。
- 児童追加は取込元の地区スキーマと合成結果の描画・容量予算を検査し、児童行だけを一括確定する。役員・自治会・旗振り・地区設定・記憶パスワードは保持する。利用者回答に従い、次年度化済み名簿をそのまま追加し、進級処理を行わない。
- 件数・異なる地区名・既存行または追加ファイル内の同姓同名同学年の可能性を1回の確認で知らせる。自動削除や同一人物への推測統合は行わない。名簿参照の比較は集合を使い、行数に対する二重走査を避ける。

## テスト先行実施

- 本番修正前の単体再現10件はすべて失敗した。その後、追加した境界テストを含む13件を、`git archive HEAD`（`9046f37`）で隔離した修正前コードへ配置して再実行し、13件すべての失敗を確認した。保存記録は `/tmp/kogaidocs-followup-baseline-red.log` である。サンドボックス内で子プロセス起動が失敗した記録とは区別する。
- 実Chromiumの修正前再現3件は、入力上限欠落、役員ファイル誤分類、旧長文の再起動後解除失敗をそれぞれ検出した。記録は `/tmp/kogaidocs-followup-ui-red.log` である。
- 正常系・境界値は4096/4097文字、旧長文の全文保持、次年度役員取込と児童追記、6年生・学年・組・班長・学区外の維持、暗号化出力・再起動を扱う。
