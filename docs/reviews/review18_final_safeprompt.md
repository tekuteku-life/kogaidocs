## 3. ユーザー指摘の是正検証および機能・UX監査

### 3.1 `safePrompt` フェイルセーフ機構（`js/utils.js`）
- **仕様と防護メカニズム**:
	- `window.prompt` または `globalThis.prompt` を安全に呼び出し。
	- Chromium Sandbox、WebView、iframe、スタンドアロンPWA等で `prompt()` が非サポートまたは `Error: prompt() is not supported.` などの例外を投げる環境下において、`try ... catch` で確実に捕捉。
	- `console.warn` による開発者向け情報出力を実施した上で、安全に `null` を返却。
	- これにより、未処理例外（`Uncaught Error`）によるアプリケーション停止・クラッシュを完全に根絶。
- **検証結果**:
	- `tests/unit/utils.test.js` において、通常入力・例外送出・ユーザーキャンセル・未定義・Node/global環境の全5パターンで正常動作を確認。

### 3.2 代表地区切り出し出力のフォールバック案内UX（`js/rep.js`）
- **仕様とユーザー導線**:
	- パスワード決定優先順位：引数明示 ＞ 代表保存用パスワード（`#rep-pass`） ＞ `safePrompt`。
	- パスワードが未取得（未入力 / prompt非サポート / キャンセル）の場合：
		1. 親切な案内ダイアログ（`alert`）を表示：「地区「〇〇」の切り出し出力にはパスワードが必要です。\n「5. 代表統合マスターデータ保存・読み込み」欄のパスワードを入力してください。」
		2. カード5（`#card-rep-master`）が折りたたまれている場合は自動展開（`toggleCard(card)` または `is-collapsed` クラス解除）。
		3. パスワード入力フィールド（`#rep-pass`）へ自動フォーカス（`passInput.focus()`）。
		4. 処理を安全に中断（`return false`）。
- **検証結果**:
	- `tests/unit/rep.test.js` (1029行目〜) において、ユーザー環境を模した例外モック下で未処理例外が一切スローされず、ダイアログ文言、カード展開、フォーカス遷移が正しく機能することを実証。

## 5. セキュリティアセスメントおよび個人情報保護法（APPI）適合性評価

### 5.1 個人情報保護法（APPI）各条文との適合性
1. **APPI 第22条（安全管理措置・漏洩等の防止）**:
	- **クライアントサイド完結暗号化**: 児童氏名、生年月日、学年、住所、電話番号、自治会役員名簿などの機微データは、すべて Web Crypto API の AES-256-GCM により暗号化されて取り扱われる。
	- **safePrompt 導入による安全管理の向上**: prompt非サポート環境下でのスタックトレース露出や、予期せぬクラッシュに伴うメモリ上の中途半端なデータ残存を防止。
	- **最小権限の原則（PoLP）**: 代表モードからの切り出し出力（`exportSingleDistrictFromRep`）において、指定地区以外の児童・役員情報、外部関係者、座席配置をディープクローン抽出時に完全除外し、他地区の個人情報混入を原理的に遮断。
2. **APPI 第23条（従業員・関係者の監督・安全管理措置の徹底）**:
	- パスワード入力のフォールバック時においても、暗号化されていない状態での平文保存を厳格に阻止。
	- `#rep-pass` への誘導により、必ずAES-256-GCM暗号化（PBKDF2 100,000回）が施された形式で出力される導線を強制。

### 5.2 暗号鍵・パスワードのメモリ保護および非暗号化ストレージ対策
- **ストレージ保存ガード**: `state.js` にて実証済みの通り、ストレージが暗号化されていない状態ではファイル保存パスワード（`savedFilePassword`）が LocalStorage へ永続化されないハードガードを維持。
- **メモリ管理**: ダイアログで入力されたパスワードは局所スコープ内でのみ使用され、不要となった時点でガベージコレクションの対象となる設計を堅持。
