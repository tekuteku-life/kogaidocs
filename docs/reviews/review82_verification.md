## 3. 手戻りの経緯と品質基準の区別

- Gate 1 は初回から5回目で PASS した。その後、実装担当が見つけた横展開（暗号化設定の未検証書込み）と、Gate 2・Gate 3 で判明した仕様の未定義・矛盾について、計9回の差分確認を受け、すべて PASS した（review79）。
- Gate 2 は3回目で PASS した。その後、実装中の全テストで判明したフィクスチャ修正・既存テストの更新、および Gate 3 由来の検査について、計3回の差分確認を受け、すべて PASS した（review80）。
- 実装中の最初の全実行では967件中26件が失敗した。原因は次のとおり。いずれも原因に応じて上流（仕様・テスト）へ戻して修正した。
	- 新仕様に沿わない既存フィクスチャ（学年なし・氏名なしの児童、死にコード `#d-file-pass` への依存、不正値の直接保存）
	- 静的検査が検出した `beforeunload` の重複登録
	- データキー以外への保存前検証の適用
	- テスト補助の自動暗号化が保存停止と衝突したこと
	- `ui.waitFor` へ Promise を渡していた待機条件の誤り
- 修正後の全実行では、`js/handoff.js` の Branch が 94.69% と基準を割った。到達しない分岐（死にコード）を削除し、未網羅分岐の試験を追加して 99.14% とした。途中の成功を基準達成とは扱っていない。
- Gate 3 は1回目で3件の指摘を受け、是正後の2回目で PASS した（review81）。
