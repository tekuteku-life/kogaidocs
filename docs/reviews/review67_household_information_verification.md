# 家庭情報入力モードの改修・検証記録

**対象**: 2.10.0 / `feature/household-information-form`<br>
**確認日**: 2026年11月11日<br>
**確認者**: 実装担当である。独立したGate 1〜3のレビューは未実施である。

## 要求と実装

- モード名称を「家庭情報入力モード（新入生・転入生）」へ変更した。家庭欄は上部の住所・電話番号だけであり、その下に児童の氏名（姓・名）・学年・組を追加する。保護者氏名は入力・提出項目に含めない。
- 提出ファイル名は `家庭情報データ.txt` の固定名である。児童名は暗号化本文に格納し、ファイル名へ含めない。
- 専用URL共有ボタンと未使用ラッパーを削除した。上部の共有ボタンは現在のモードだけをクエリに含め、余分なクエリやフラグメントを共有しない。紹介文は新入生・転入生の両方を対象とする。
- パスワード案内は、提出先の指定があれば使用し、指定がなければ自分で設定して別途伝える文言である。半角英数記号12文字以上の制約は維持する。
- 旧 `?mode=transfer` と旧提出ファイルの受入を維持する。旧下書きの先頭児童から住所・電話を家庭欄へ補完する。意図して空欄へ戻した値は旧児童情報から復活させない。旧 `class` は描画時に `className` へ補完する。
- 新提出はversion 2とし、家庭の住所・電話を直下と各児童へ複写して旧受入処理との互換性を保つ。児童出力は許可した項目から構築し、旧ふりがなや余剰フィールドを出力しない。

## 実装担当による確認

家庭欄の文字列はDOMのvalueへ設定し、HTMLとして挿入しない。児童欄は既存のエスケープを維持する。家庭欄の更新対象はイベント処理と更新関数の双方で住所・電話だけを許可する。ローカル保存・復元・ブラウザ引き継ぎで新しい家庭欄の型と4096文字上限を検証する。ファイルとコピーは共通の必須検査・ペイロード生成を通す。ロック・提出後消去では家庭欄・児童欄・パスワードを消去する。

`household-transfer.test.js` は家庭欄と児童欄の空白・範囲外学年・4096/4097文字・不正型・旧下書き移行・復元/消去・実暗号化往復・地区と代表への取り込みを検証する。`headless-household.test.js` は旧下書きの組名・未入力学年の提出経路と、390px/1280pxで表示順、横幅、項目数、追加、暗号化ファイル/コピー、上部共有、パスワード案内、実再起動と消去を検証する。既存の共有・必須検査・XSS・統合テストも変更後の画面を通す。

全体確認中に共有URLの旧期待値が1件残っていたため、新仕様の `?mode=district` に修正した。暗号化処理や共有APIの実装不具合ではなく、変更仕様に追随していない試験期待値である。修正後の全体一式を再実行した。旧下書きでclassNameが空文字かつclassに値がある場合に表示値と提出値が一致しない問題も実装担当の点検で検出し、描画時の正規化と実UI提出試験を追加した。未入力学年が1年生と誤表示されないよう空の選択肢を追加した。
