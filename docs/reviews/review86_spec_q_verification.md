- Gate 3 の4回目で、既存試験（SEC-31 の期間内のプリセット）が await されない暗号化保存の完了を待たずに再ロックしており、同一コードでも失敗しうることを指摘された（HEAD でも起きる）。テスト（Stage 4）へ戻り、保存値が変わるまで待つ形に改めた（同じ形の2件も改めた）。Gate 2 の差分確認（27回目〜）で同じ根の試験がもう1件指摘され、同じ形に改めた。同時に指摘された本記録と review84 の文書の不備は並行して直した。
- 最終コードでの全件試験（第2節）の後、Gate 3 の5回目の指摘は文書だけ（開発プロセス定義書の Gate 3 後の文書の確かめ方、本記録群の文言、設計書の改訂日）となり、通過とした。指摘は並行して直し、PR 本文に列挙して PR レビューで確かめる（review85）。
- 全件試験・Gate の指摘で見つかった試験側の不備を、原因に応じて直した。期待値は変えていない。
	- 自動ロックの試験（`headless-workflows`・`headless-security`）が予約の遅延を 900000ms ちょうどで判定しており、時計が進むと予約を見落としていた。判定を「14分を超え15分以下」に広げた。期限が操作で延びることは、予約時刻と遅延の記録から確かめるようにした（Gate 2 差分6回目）。
	- 既存の実Chromium 試験「UI SEC-34: a save waiting for the exclusive lock …」が、`isStorageUnlocked()` だけを待っていた。これは鍵の解除直後に真になるため、保存値の読込完了の前に検査して失敗することがあった（HEAD のコードでも単独実行6回中2回）。同じファイルの他の試験と同じく、解除画面が閉じるまで待つ条件に改めた。改めた後は単独で10回連続で合格した（Gate 2 差分8回目）。
	- 座席の試験で置いたセルが座席表の範囲外で、地区詳細モーダルの保存が検証で拒否されたまま「座席が変わらない」期待値が素通りで合格していた（Gate 2 差分17回目）。範囲内に直し、座席の試験のモーダル保存すべてに保存の失敗がないことの確認を加えた。
	- `security-save-invariant.test.js` の SEC-31・SEC-30・SEC-35 の3件が、await されない保存の完了を `setTimeout(resolve, 0)` で待っていた（Gate 3 の4回目）。保存値が変わるまで待つ補助関数（`tests/helpers/dom-mock.js` の `waitForStoredChange`）に改め、カバレッジ付きの12回の繰返しですべて合格した。
	- `chairman-fiscal-year.test.js` の取込の拒否の試験が、出席のトグルの保存（await されない）の完了を待たずに、後の明示の保存の後で保存値を控えていた（Gate 2 差分27回目）。単体試験の模擬のロックは排他をかけないため、先の保存が後から古い値で上書きしうる。同じ補助関数で待つ形に改めた。保存の完了順を入れ替える変異のもとで、単体・結合試験の795件がすべて合格した。
- 途中の成功を基準達成とは扱っていない。

## 4. 仕様確認事項・残余リスク・未検証境界

- SPEC-Q3（年度更新時の旗振り下書きの破棄）は、利用者の決定により変更していない。
- 自治会役員の座席の照合を本人単位にしたことで、旧版と結果が異なる場合がある（E-13-02「座席の旧版との差」の (1)〜(4)）。いずれも、同じ本人を確かめられる場合だけ座席を引き継ぐ方向の差である。
- 旧版の出席セレクタは、名簿の異なる同名エントリへも行番号で同期していた。その結果、別の本人に付いて保存された値は区別できない。この値は、照合（印刷対象の切替など）や取込で代表名簿と一致しなければ解除され、代わりの比較元からは会長以外の行の `true` を引き継がない（E-13-02）。それまでは保存値に残りうる。
- 残余リスク R-SEC-A〜D は前回の記録（review82）のとおりで、今回は変更していない。
- 未検証境界: 前回の記録（review82）のとおり。本番HTTPSのTLS・HTTPヘッダー、実機 iOS/Android、実WebAuthn認証器、OSの印刷・共有・クリップボード履歴、本番配信での Service Worker 更新は、ローカル試験では保証しない。
- 外部工程: コミット・リモート push・PR の更新は本記録の後に行う。結果は PR 本文に記載する。
