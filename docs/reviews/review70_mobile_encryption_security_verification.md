## 追加セキュリティ工程

通常改修後に[追加アセスメント](review69_followup_security_assessment.md)を行い、攻撃再現試験を先に実装した。

- SEC-22: 設定・解除を中断しても遅い完了が鍵を開放する経路を実WebCryptoで再現した。操作世代・暗号側確定guard・読込採用前guard・中断時の鍵破棄を追加した。生体認証の遅延完了と鍵有効化直後の中断も単体で検査した。
- SEC-23: 全モードのファイル・コピー・共有・代表地区切出しで、ロック後にも出力する8経路を再現した。開始時の保存世代と認証メタデータを出力前に照合した。別タブ通知前の認証情報削除も先行再現し、読込不能時も拒否する。追加で、クリップボード失敗後に代替表示/ダウンロードへ漏れ戻る2経路を再現・是正した。既にOSへ渡した出力を撤回できるという意味ではない。
- SEC-24: 暗号化待機中の地区・班編集で、本文と見出し/ファイル名が異なる2経路を再現し、識別情報も本文の取得時点に固定した。

## 失敗の分類

- 制限環境の初回UI起動失敗は、許可された同一コマンドでの再実行により製品の再現失敗と分離した。
- 旧UI試験の平文前提を必須暗号化へ更新した。準備では実際の設定画面・WebCryptoを通し、解除を自分で検査する試験には自動解除を適用していない。旧平文の読込移行・原本保持は単体/結合と初回失敗再試行UIで維持した。
- static-checkの `getElementById('tab-')` は文字列連結を固定IDと誤認する検査側の制約であった。動的IDをテンプレート表記へ統一し、未知のIDを許容する除外は追加していない。
- DOMモックのカンマ区切りclosest未対応は、対象試験のフォーム識別だけを補完した。実ブラウザのフォーム選択試験も別に行った。
- 修正途中の全体成功・部分カバレッジは最終結果とはしない。最後の実行では本番・試験ソースを固定した。
