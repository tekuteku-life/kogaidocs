# ハタフロット統合・iOS導線の検証記録

**履歴**: 本書は追加要件前の設計・検証記録である。JSON保存の廃止、ライセンス通知不要、LINE引き継ぎ、pushについては [追加要件の設計](review63_browser_handoff_design.md) と最終検証記録を優先する。

検証日は2026年11月10日である。対象は作業ブランチ `feature/hata-full-integration`、バージョン2.9.0のローカル変更である。比較元と設計判断は [機能比較・設計記録](review61_hata_integration_design.md) に示す。

## 再現と修正

- 先行した `node tests/unit/hata-complete.test.js` の4件は全件失敗した。空タイトルが既定値に戻ること、再生成で外部名簿が児童名簿へ置換されること、LINE本文生成と重複警告が未実装であることを確認した。
- 全旗振り入力を空文字・空配列・falseも含めて収集し、地区の暗号化ファイルと上流JSONで往復するよう修正した。再生成・再描画時の無条件名簿同期を削除した。
- 従来の漏洩試験は「外部名簿を使わず児童名簿へ置換する」という旧動作をassertしていた。新仕様に合わせ、悪意文字列を含む外部名簿を保持し、児童名簿を変更しないことへ変更した。攻撃DOM・イベント実行・通信の検査は維持した。
- PDF名のassertionをタイトル・印刷地区名・作成日の構成へ更新した。年度更新の単体試験は実UIと同じくフォームを描画してから操作し、印刷地区名と世帯集約設定の保持も確認した。
- 暗号化ファイル出力中の追加編集によって古い保存状態を表示しないよう、出力開始時の設定スナップショットと照合する。

## iPhoneの確認範囲

- 既存HTMLにstandalone指定・status-bar指定・apple-touch-iconがあることを確認した。アプリ名のmetaタグと、Safariの共有メニューによる追加案内を補った。
- NodeではHTTPS・通常HTTP・fileとiPhone/Mac型iPad/standaloneの条件、プロンプト消費、appinstalledを検証した。AppleアイコンのPNG実体と192×192寸法も確認した。
- ChromiumのiOS型UAでは端末判定、metaタグ、native dialogの表示・閉じる・Escapeを確認した。file起動のボタン非表示を確認し、案内開閉自体は関数を呼んで検証した。
- 別途試みたローカルHTTP試験はPage.navigateで20秒タイムアウトし、テスト用HTTPサーバーの受信もなかった。原因は確定しておらず、HTTP配信やSafariの成功証拠として採用していない。
- iPhone実機でのSafari共有→ホーム画面追加→独立起動、OSの保存・印刷・共有ダイアログ、本番TLS・HTTPヘッダー、実際のインストール済みPWA更新は未検証である。
